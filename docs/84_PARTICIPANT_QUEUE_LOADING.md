# 참여자 제출 처리 코드의 초기 로딩 분리

2026-10-15.

## 변경

앱 셸은 모든 계정에서 `submissionQueue`를 정적으로 불러왔지만, 자동 처리는 활성 참여자에게만 시작했다. 로그인·관리자·교육담당자 화면에도 제출·저장 구현의 다운로드 비용이 있었다.

활성 참여자를 확인한 뒤 모듈을 비동기로 불러오도록 분리했다. 초기 화면의 렌더링을 기다리게 하지 않으며, 기존 자동 제출·확정 영수증 정리·IndexedDB 처리 구현은 유지했다. 계정 변경이나 로그아웃으로 소유자가 바뀌면 이전 계정의 늦은 모듈 로드로 처리를 시작하지 않고, 이미 시작된 처리와 이벤트 수신기를 정리한다.

모듈 로드 실패 시 화면은 유지하고 재연결·창 복귀·화면 표시 이벤트에서 다시 시도한다. Chromium 전송 실패 테스트에서 실패한 모듈 URL이 기억되어 재연결만으로 재요청되지 않는 경우를 관찰했다. 해당 경우에는 ‘대기 결과 확인을 시작하지 못했습니다’와 사용자가 선택할 수 있는 ‘앱 다시 불러오기’를 제공한다. 자동으로 페이지를 새로고침하지 않는다.

## 빌드 측정

기준선: `eb4a8c7cf4d72d95c10935b259edc712432aa37d`. 동일한 로컬 프로덕션 설정에서 manifest의 `index.html`과 정적 JS 의존성만 합산했다. gzip은 각 파일을 같은 Node 설정으로 압축해 합산했다.

| 최초 앱 셸 JS | 변경 전 | 변경 후 | 감소 |
|---|---:|---:|---:|
| 원본 | 531,883 B | 514,839 B | 17,044 B · 약 3.2% |
| gzip | 153,469 B | 149,321 B | 4,148 B · 약 2.7% |

로그인·운영 계정은 참여자 제출 모듈을 요청하지 않는다. 참여자는 인증·프로필 확인 이후 필요한 코드를 추가로 받으므로 이 수치를 참여자의 전체 이용 전송량 감소나 실제 LCP·로딩 시간 개선율로 해석하지 않는다. CSS·이미지·오디오·API 응답도 이 측정에서 제외했다.

빌드의 queue 동적 모듈이 최초 정적 그래프 밖에 있는지 경로 검사에 추가했다. 최초 JS 상한은 원본 510 KiB / gzip 150 KiB로 강화했다. Vite의 단일 chunk 500 kB 권고 경고는 여전히 존재한다.

## 검증

- 단위 69건 통과: 지연 로더/처리 수명주기 5건, 기존 로더 3건, 제출 커밋 회귀 61건.
- 모바일 360px·390px에서 캠페인과 실제 IndexedDB 모의 제출 검증 46건 통과. 참여자만 모듈 요청, 운영 계정의 요청 없음, 전송 실패 안내·명시적 앱 재로딩 복구, 기존 오프라인 동시성·불변성·보존 확인.
- lint, TypeScript·프로덕션 빌드, 초기 JS 용량·경로 분리·클라이언트 비밀정보·승인 해시 검사 통과.
- 실제 참여자 기록은 읽거나 생성하지 않았다. 시나리오 내용·승인·서버·DB는 변경하지 않는다.
