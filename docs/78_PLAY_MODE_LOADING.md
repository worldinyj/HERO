# 튜토리얼과 경쟁 플레이 코드 분리

2026-10-15. 첫 화면의 운영 경로는 이미 지연 로딩되고 있었으나, 기존 `GamePage`는 튜토리얼과 경쟁 플레이를 함께 가져왔다. 튜토리얼 이용 시에도 경쟁 서버 제출·리플레이와 실사건 회고 코드가 다운로드되는 구조였다.

## 변경

`GamePage`를 경로 선택용 작은 화면으로 바꾸고, 기존 튜토리얼 구현은 `TutorialGamePage`로 이동했다. `s00_tutorial`은 튜토리얼 모듈을, 다른 장은 경쟁 모듈을 지연 로딩한다. 브리핑에서는 선택한 모드와 경로 모듈을 병렬로 미리 불러온다. 다운로드 실패는 기존 화면 복구 안내와 전체 새로고침으로 복구한다.

경쟁 장 ID가 바뀌면 해당 장의 컴포넌트를 새로 구성한다. 튜토리얼·경쟁의 진행·회고·점수·서버 제출 동작, 시나리오 본문과 승인 해시는 변경하지 않는다.

## 빌드 측정

빌드 manifest의 정적 의존 그래프에서 최초 앱 셸에 이미 포함된 JS를 제외하고, 경로 선택 모듈과 해당 모드가 추가로 요구하는 JS를 합산했다. gzip은 같은 로컬 Node 설정으로 각 파일을 압축해 합산한 값이다.

| 진입 경로 | 변경 전 원본 JS | 변경 후 원본 JS | 변경 전 gzip | 변경 후 gzip |
|---|---:|---:|---:|---:|
| 튜토리얼 | 158,881B | 138,832B | 47,670B | 43,235B |
| 경쟁 플레이 | 158,881B | 149,789B | 47,670B | 46,011B |

튜토리얼 추가 JS는 원본 약 12.6%, gzip 약 9.3% 감소했다. 경쟁 추가 JS는 원본 약 5.7%, gzip 약 3.5% 감소했다. 첫 앱 셸·CSS·이미지·음성·API 응답은 이 수치에 포함하지 않는다. 브라우저 캐시와 사전 로딩에 따라 실제 전송량은 달라지며, 이 수치가 로딩 시간 감소율을 뜻하지 않는다.

## 검증

- 빌드 검사: 두 모드가 별도 동적 진입점이며 최초 정적 그래프와 서로의 정적 그래프에 포함되지 않음.
- 모바일 360px·390px: 선택한 모드만 요청, 튜토리얼에서 경쟁 시작 API 미호출, 각 모드 다운로드 실패 → 복구 안내 → 새로고침 복구.
- 기존 경쟁 회고 선택 제출·결과 표시를 함께 확인한다. 전체 CI에서는 튜토리얼, 경쟁 완료·오프라인 대기 등 기존 회귀 검사도 수행한다.
- TypeScript, ESLint, 프로덕션 빌드·경로 분리 검사 및 클라이언트 비밀정보 검사.

실제 참여자의 이용 확인과 파일럿 상세 의견은 별도 대기 항목으로 유지한다.
