# 담당자 참여 현황 조회 지연 복구

## 기준과 범위

- 2026-10-29 KST 기준 `main`의 `b54546325a05c2d2e4da512bd3e8ea3c3bc446e7`에서 분기했다.
- PR #114(담당자 검색), #140(사업소·대기 초대 구간 조회), #141~142(관리자 조회 복구)는 이미 병합된 작업이다. 이를 다시 구현하지 않는다.
- 이번 변경은 `/manager`의 참여 현황 읽기 복구다. DB·RPC 정의·RLS·쓰기 API·시나리오 승인·음원은 변경하지 않는다.

## 변경

- 기존 읽기 RPC `manager_player_rows`, `manager_pending_invites`, `manager_job_aggregates`를 공통 조회 함수로 모았다. 기존 POST 호출 방식·권한 범위·응답 검증을 유지한다.
- 기존 `readWithDeadline`의 15초 제한과 AbortSignal을 적용한다. 취소를 무시하는 전송도 대기를 끝내며, 이후 응답은 새 화면 상태로 반영하지 않는다.
- 새 읽기 시작·화면 이탈 시 이전 읽기를 취소하고 기존 revision gate로 늦은 응답을 배제한다. 명시적인 `참여 현황 다시 조회` 버튼을 제공한다.
- 읽기 실패 시 이전 참여자·대기 초대·직무 집계는 지운다. 미확인 결과를 0명이나 n<5로 표시하지 않는다. 읽는 동안 남은 이전 명단은 최신 결과가 아니라고 안내한다.
- 현재 읽기가 미확인인 동안 기존 사용자 상태 변경·닉네임 초기화·초대 재발급/취소 버튼과 실행 경로를 막는다.
- 모든 새 읽기는 담당자 화면의 초대/상태/닉네임 대조 완료 상태를 무효화한다. 읽기가 끝났다는 이유만으로 불확실한 쓰기 잠금을 해제하지 않는다. 단건·CSV 초대의 잠금 해제도 현재 명단 확인 성공을 추가로 요구한다.
- 초대 패널을 재마운트하지 않아 이미 표시된 일회용 링크·CSV 결과를 보존한다. 읽기 재시도로 쓰기를 자동 재전송하지 않는다.

## 확인한 결과와 미확인 범위

- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` 통과.
- 초기 JavaScript 용량 예산·경로 청크 분리·클라이언트 비밀정보 검사 통과. 용량 검사를 실제 LCP 측정으로 간주하지 않는다.
- 엔진 25개 + 웹 444개 = 469개 단위 테스트 통과. 신규 조회 계약 9개는 실제 설치된 Supabase 클라이언트와 모의 fetch를 사용해 RPC 대상, 신호 전달, 오류/잘못된 응답, 15초 제한, 취소, 늦은 응답을 확인한다.
- 신규 Playwright 시나리오 10개를 360×800·390×844 두 화면에서 총 20개 수집한다. 조회 오류·지연, 수동 복구, 링크 보존, 오래된 대조 결과의 잠금 해제 차단을 포함한다.
- **브라우저 실행 미검증:** Chromium 다운로드가 손상된 ZIP/0 MiB 응답으로 실패했다. 대표 테스트 실행도 브라우저 실행 파일 부재로 시작 단계에서 실패했다. 테스트 수집은 실행 성공이 아니다.
- 실제 로컬/운영 Supabase 질의, 새 권한 감사, 실기기, 운영 배포는 이번 변경의 검증 근거가 아니다. 모의 응답 검증을 실제 DB 통합 검증으로 기록하지 않는다.

## 다음 검증

Chromium이 설치된 개발 환경에서 다음을 실행하고, 미확인 쓰기의 재시도 잠금과 일회용 링크가 보존되는지 확인한다. 통과 전에는 초안 PR을 병합·배포하지 않는다.

```bash
pnpm exec playwright test e2e/manager-dashboard-recovery.spec.ts
pnpm exec playwright test e2e/invite-play-leaderboard.spec.ts
```

두 번째 파일은 별도의 로컬 Supabase 테스트 환경·기존 E2E 준비 절차가 필요하다. 운영 데이터로 실행하지 않는다. 전체 명단의 서버 페이지 처리는 이번 읽기 복구에 포함하지 않는다.
