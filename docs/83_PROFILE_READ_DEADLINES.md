# 개인 기록·회고 조회의 지연 종료와 재시도

2026-10-15.

## 문제와 변경

`/me`의 개인 기록 요약과 선택적으로 불러오는 회고 조회에는 응답 대기 제한이 없었다. 연결이 끝나지 않으면 기록 화면이 계속 로딩 중이거나 회고 버튼이 잠겼다. 요약 조회의 오류 화면에도 재시도 수단 없이 로그아웃만 있었다.

두 읽기 요청에 15초의 대기 제한을 적용했다. 제한에 도달하면 지연 안내를 표시하고 수동 재시도를 허용한다. 기록 요약 오류 화면에 ‘기록 다시 불러오기’를 추가했으며 로그아웃도 유지한다. 회고 새로고침 중 이전 기록을 유지하는 기존 개선도 유지한다.

화면을 벗어나면 조회를 취소한다. 전송 계층이 취소를 무시하더라도 호출은 종료되며, 늦게 도착한 성공·실패가 새 조회 결과를 덮어쓰지 않는다. 요청이 끝나면 타이머와 취소 수신기를 해제한다.

## 범위

`readWithDeadline`은 읽기 요청에만 사용한다. 적용 대상은 `my_record_summary`와 `my_reflection_history` RPC다. 닉네임 변경·결과 제출·초대 등 쓰기 요청과 그 성공 여부 판정에는 적용하지 않는다. 자동 재시도는 추가하지 않았다. 인증·시나리오 콘텐츠·DB·권한·점수는 변경하지 않는다.

## 검증

- 조회 도우미 단위 검증 4건: 정상 응답/오류의 타이머 해제, 취소를 무시하는 요청의 대기 종료와 후속 조회, 화면 이탈 취소 및 이미 취소된 요청의 시작 방지.
- 기존 회고 응답 검증 2건 통과.
- 360px·390px 모바일 20건 통과. 가상 시계로 최초 회고 조회와 기존 목록을 가진 회고 새로고침, 요약 조회를 각각 15초 지연시킨 뒤 수동 재시도·정상 복구·늦은 응답 무시 확인.
- 기존 네트워크·손상 응답 회복, 빈 기록 구분, 정확한 과거 버전·HP 유지, 관리자·교육담당자 회고 조회 제외 유지.
- lint, TypeScript·프로덕션 빌드, 초기 JS 용량·경로 분리·클라이언트 비밀정보·콘텐츠 승인 해시 검사 통과.

브라우저 검증은 loopback 모의 API와 테스트 데이터로 수행했다. 실제 참여자의 기록 조회·생성 또는 느린 실기기 환경의 체험 확인을 대신하지 않는다.
