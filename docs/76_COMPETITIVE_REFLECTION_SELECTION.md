# 경쟁 플레이 회고 선택 보존

2026-10-15. 참여자 실사용 확인은 대기 상태로 두고 독립적으로 진행한 개선이다. 사용자의 ‘제대로 진행된다는 가정’은 실제 참여자 완료·저장 검증으로 기록하지 않는다.

## 변경

기존에는 ‘어느 시점부터 방벽이 약해졌을까요?’의 응답 여부만 평가에 사용하고 선택한 시점은 제출하지 않았다. 새 클라이언트는 선택한 `initial_conditions` 또는 판단 노드 ID를 선택 필드 `reflectionSelection`으로 제출한다. 서버는 행동 로그를 재실행한 뒤 실제로 도달한 판단 노드인지 검사하고, 기존 완료 트랜잭션의 `evaluation` JSON에 함께 저장한다. 별도 테이블이나 마이그레이션은 필요하지 않다.

서버가 확인한 응답에 선택 정보가 있으면 HP 리뷰에 ‘내가 돌아본 방벽 약화 시점’을 표시한다. 회고 선택에 따른 정답 판정·점수 차등은 없다. 시나리오 본문과 승인 해시, 점수 규칙은 바꾸지 않는다.

## 보존과 호환성

- 오프라인 제출 대기 기록에 선택도 포함한다. 같은 세션의 재시도·다른 탭은 먼저 저장한 선택을 변경하거나 삭제해 덮어쓸 수 없다.
- 서버 완료 기록은 기존 원자적 완료 계약을 따른다. 중복 제출은 최초 결과와 회고 선택을 반환하고 다시 저장하지 않는다.
- 선택 필드가 없는 이전 클라이언트·기존 대기 제출·과거 완료 기록도 처리한다. 과거 회고 선택을 만들어 채우지 않는다.
- 새 프런트엔드보다 서버 함수를 먼저 배포해야 한다. 이전 서버는 새 선택 필드를 저장하지 않으므로 서버 반영 없이 보존 완료라고 보고하지 않는다.
- 제출 전 새로고침한 회고 화면의 선택·단계 복원은 이번 범위에 포함하지 않는다. 제출 대기 기록이 만들어진 이후의 선택 보존과 구분한다.
- 개인 ‘내 기록’ 화면에 회고 상세 조회를 추가하거나 Notion에 자동 전송하지 않는다. 이번 표시 위치는 완료 후 HP 리뷰다.

## 검증

- 제출 입력: 구형 필드 생략 허용, 선택 원문 보존, 잘못된 타입·길이·미응답 선택 거부, 미방문 분기 거부.
- 제출 대기: 같은 내용 재시도 허용, 선택 변경·삭제 충돌 거부, 실제 브라우저 IndexedDB 두 탭에서 최초 선택 보존.
- 모바일: 360px·390px에서 최초 조건/판단 장면 선택 → 회고 → 제출 → HP 리뷰 표시. 선택 필드 없는 구형 서버 응답도 표시 오류 없음.
- DB: 선택 저장 및 중복 요청이 최초 선택을 덮어쓰지 못함을 pgTAP로 확인한다.

이 검증은 격리된 테스트 계정·응답·DB를 사용한다. 실제 참여자 완료·학습 효과·운영 데이터의 S02 회고 응답 확보를 뜻하지 않는다.
