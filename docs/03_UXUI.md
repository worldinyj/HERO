## 1. 디자인 방향

### 1.1 콘셉트 — "작전도 위의 하루"
공명전의 **장(章) 지도 · 초상화 대화 · 책략 카드 · 공적 평가** 문법을, 원전의 **주제어실 패널 · 작업허가서 · 계통도** 질감으로 번안한다.

| 키워드 | 시각 언어 |
|---|---|
| 긴장감 | 어두운 네이비 배경, 계기판 앰버(Amber) 강조 |
| 기록 | 작업허가서/절차서 종이 질감 카드, 고정폭 숫자 |
| 사람 | 반신 초상화(일러스트), 말풍선 대신 하단 대사창 |
| 절제 | 사건 연출은 폭발·경보 남발 금지 — 지시값 정지, 무전 잡음, 화면 채도 저하 |

> IP 원칙: 공명전의 그래픽·캐릭터·UI를 모사하지 않는다. 구조(장 구성·대화·카드·평가)만 차용하고 모든 아트는 자체 제작한다.

### 1.2 디자인 토큰

| 토큰 | Light | Dark(기본) | 용도 |
|---|---|---|---|
| `--bg` | #F4F1EA (종이) | #0E1624 (주제어실) | 배경 |
| `--surface` | #FFFFFF | #16213A | 카드·패널 |
| `--ink` | #1B2333 | #E8ECF4 | 본문 |
| `--muted` | #5B6578 | #8A96AD | 보조 |
| `--accent` | #C77700 | #F2A541 (앰버) | 강조·선택·시계 |
| `--safe` | #2E7D5B | #4CC38A | 안전 정지·완수 |
| `--warn` | #B26A00 | #F5B83D | 근접오류 |
| `--danger` | #B3261E | #F2685C | 사건 |
| `--barrier` | #2F5DA8 | #6FA0FF | 방어막 카드 |

- 상태 표현은 **색 + 아이콘 + 텍스트** 3중 (색약 대응).
- 서체: **Pretendard** (본문·UI), 시계·수치는 `font-variant-numeric: tabular-nums`. 장 제목만 붓글씨 계열 웹폰트 1종(라이선스 확인, 예: 공개 라이선스 서체) 허용.
- 기본 테마 **Dark**, 설정에서 Light 전환.

### 1.3 그리드·크기 (모바일 우선)
- 기준 뷰포트 360×640, 최대 콘텐츠 폭 480px(데스크톱에서는 중앙 정렬 + 좌우 여백에 일러스트)
- 좌우 거터 16px, 8pt 간격 시스템
- 터치 타깃 ≥ 44×44, 선택지 버튼 높이 ≥ 52px
- 엄지 영역: **주요 행동은 하단 40%** 에 배치
- Safe-area(노치) `env(safe-area-inset-*)` 적용

### 1.4 사운드 디자인 원칙
- **BGM은 분위기, SFX는 피드백** 역할만 수행한다. 정답·위험도 같은 핵심 정보는 소리로 암시하지 않는다.
- 음악은 instrumental 중심, 대사 가독성을 해치지 않는 저중역/저밀도 편곡을 기본으로 한다.
- 실제 원전 경보음·설비음·비상방송처럼 들리는 음향은 사용하지 않는다. 이벤트 주의음은 추상적이고 짧은 UI tone으로 제작한다.
- 최초 플레이 시 `소리 켜고 시작` / `무음으로 시작`을 선택한다. 소리를 선택한 경우에도 첫 사용자 제스처 이후에만 오디오가 활성화된다.
- 설정에서 **음악 / 효과음 각각 On·Off와 볼륨**을 조절할 수 있다.
- `prefers-reduced-motion`과 별개로 `reduced-sensory` 옵션을 제공해 강한 진동·플래시·효과음 피크를 낮춘다.

## 3. 핵심 사용자 흐름

### 3.1 초대 → 첫 플레이 (목표: 3분 이내)
```
카톡 초대 메시지 [초대 수락하기] → [초대 미리보기] → [카카오로 시작하기]
 → 이름 확인·닉네임·동의 → [튜토리얼 장 0: 30초]
 → [캠페인 맵] 1장 하이라이트 → [장 소개] → 플레이
```

### 3.2 플레이 루프
```
대사(scene) ─▶ 결정(decision) ─┬─ 선택지 → 시계 진행 → 다음 장면
                               ├─ 정보 행동(절차서/동료/MCR) → 정보 공개 + 시간 소모 → 같은 결정으로 복귀
                               └─ 방어막 카드 → 카드 연출 + 시간 소모 → 같은 결정으로 복귀
   ... (숨은 hazard 판정) ... ─▶ 이상징후(event) ─▶ 결정 ─▶ 엔딩
```

### 3.3 결과 → 리플레이
```
엔딩 컷 → "어느 시점부터 방어막이 약해졌을까요?" (결정 타임라인에서 1개 선택)
 → "한 순간이 아니라 여러 조건과 방어막의 누적" 피드백 → Swiss Cheese 공개 → HP 리뷰(5대 지표) → 실사건 공개 → [리플레이: 결정 지점 선택] / [다음 장]
```

## 4. 화면 설계

### 4.1 로그인
```
┌──────────────────────────┐
│        H E R O           │
│ 사고는 마지막 행동에서     │
│   시작되지 않는다          │
│                          │
│ [ 💬 카카오로 시작하기  ]  │
│                          │
│ 카카오톡 초대를 받은 분만    │
│ 이용할 수 있습니다          │
│ ⓘ 플레이 결과와 순위는      │
│   인사평가와 무관합니다      │
└──────────────────────────┘
```

### 4.2 카카오톡 초대 → 수락(온보딩)

**카톡 메시지 (피드형)**
```
┌──────────────────────────┐
│ [HERO 대표 이미지]         │
│ HERO 초대장               │
│ ○○발전소 · 현장운전원으로   │
│ 초대되었습니다 (~10/14)     │
│ [   초대 수락하기   ]      │
└──────────────────────────┘
```

**초대 미리보기 (/i/:token)** — 로그인 전
```
┌──────────────────────────┐
│ 홍길동 님,                 │
│ ○○발전소 교육담당 김OO 님이 │
│ HERO에 초대했습니다         │
│ 소속 ○○발전소 · 현장운전원   │
│ 유효기간 10월 14일까지       │
│ [ 💬 카카오로 시작하기 ]    │
└──────────────────────────┘
```
- 만료/사용됨/취소 링크: "이 초대 링크은 사용할 수 없습니다. 담당자에게 새 링크를 요청하세요."
- 카카오톡 인앱 브라우저 기준 레이아웃. PWA 설치 안내는 "외부 브라우저로 열기" 후 노출

**온보딩 3단계**
1. 본인 확인: "홍길동 님이 맞습니까?"
2. 닉네임(중복 실시간 검사, 2~12자, 금칙어 필터) — "리더보드에는 닉네임만 표시됩니다. 실명은 공개되지 않습니다."
3. 약관·개인정보 동의 + **"플레이 결과와 순위는 인사평가와 무관합니다"** 고지 확인

### 4.3 캠페인 맵 (홈)
```
┌──────────────────────────┐
│ 10월 시즌 · D-24      ⚙  │
│ 상위 12% · 1,240 HP      │
├──────────────────────────┤
│   ◉ 0장 튜토리얼 ★★★      │
│    ╲                     │
│     ◉ 1장 "오늘 오전까지…" │
│      ╲    ★★ (재도전 가능) │
│       ◎ 2장 "아마 이 설비…"│
│        ╲                 │
│         🔒 3장            │
├──────────────────────────┤
│ 캠페인 │ 리더보드 │ 내 기록 │
└──────────────────────────┘
```
- 세로 스크롤 지그재그 경로(계통도 배관 라인 모티프), 노드 = 장
- 노드 상태: 잠김 / 신규 / 진행 중(이어하기) / 완료
- 이어하기 세션이 있으면 상단 배너

### 4.4 장 소개 (출진 화면)
- 첫 플레이에서만 출진 버튼 위에 **소리 켜고 시작 / 무음으로 시작** 선택을 노출하고 이후에는 저장된 설정을 사용한다.
```
┌──────────────────────────┐
│ ← 제1장                  │
│ 「오늘 오전까지          │
│   끝내야 합니다」          │
│ ──────────────────────── │
│ 이번 장의 관점: 작업자       │
│ ⏱ 약 7분 · 모든 직무 플레이 가능│
│ 상황: 정비 후 성능시험…    │
│                          │
│ 지급 방어막 카드          │
│ [브리핑][Peer][3-way][STOP]│
│                          │
│ [      출 발      ]       │
└──────────────────────────┘
```
- **리스크 정보는 노출하지 않음**. 주제 태그도 플레이 전에는 숨긴다.

### 4.5 플레이 화면 (핵심)

```
┌──────────────────────────┐
│ 09:35  ▸ 마감 12:00   ☰  │
│ ┌──────────────────────┐ │
│ │   [배경 일러스트]      │ │
│ │        🧑‍🔧 김 차장     │ │
│ └──────────────────────┘ │
│ ┌ 김 차장 ──────────────┐ │
│ │ 오늘 오전까지 시험 끝내 │ │
│ │ 야 해. 난 회의 들어간다.│ │
│ └──────────────────────┘ │
│ 📄절차서  🗣동료  📞MCR    │
│ ┌──────────────────────┐ │
│ │ A 차장이 돌아올 때까지   │ │
│ │   기다린다              │ │
│ │ B 전화로 승인 후 진행    │ │
│ │ C 동료에게 지원 요청     │ │
│ │ D 가능한 단계까지 먼저   │ │
│ └──────────────────────┘ │
│ [🛡 카드 3]               │
└──────────────────────────┘
```

**상호작용 규칙**
| 요소 | 동작 |
|---|---|
| 선택지 | 탭 → 선택 강조 → **확인 탭(두 번째 탭)** 으로 확정 |
| 정보 행동 | 탭 → 시계 진행 → 정보 카드 → 같은 결정으로 복귀 |
| 방어막 카드 | 트레이 탭 → 펼침 → 카드 탭 → 사용 가능/불가 사유 |
| 카드 사용 연출 | 카드 중앙 연출 + 방패 빛 + 짧은 대사 |
| 시계 | 행동 비용만큼 롤링, 마감 임박 시 시각적 압박 |
| 일시정지 | 이어하기 / 처음부터 / 나가기(자동저장) |
| 선택지 순서 | `presentation_seed` 기반 셔플, 통계는 안정적 `action_id` |

**Hidden Hazard 표현** — 숫자 대신 분위기와 현장 단서로만 표현.

**오프라인 상태**
- 이미 시작한 세션은 오프라인 배너 표시.
- 새 장 시작, 로그인, 리더보드 갱신, 결과 최종확정은 온라인에서만 가능.

### 4.6 이상징후(Event) 연출
```
│ [배경 채도 ↓, 미세 노이즈] │
│ ┌ 계기 ────────────────┐ │
│ │ 조작 후 예상했던 지시값 │ │
│ │ 변화가 나타나지 않습니다│ │
│ └──────────────────────┘ │
│ A 작업을 멈추고 보고한다   │
│ B 잠시 기다려 다시 본다    │
│ C 계속 진행한다           │
```
- 사운드: 짧고 추상적인 UI 주의음 1회. 경보 사이렌 사용 금지.
- 햅틱: 지원 기기에서 약한 진동 1회.

### 4.7 엔딩
| 엔딩 | 화면 |
|---|---|
| ★★★ 무사고 완수 | 밝은 톤, 팀원 초상화 미소, "작업 완료" 도장 |
| ★★ 안전 정지 | "작업 중지 — 지연은 사건이 아닙니다" 도장 |
| ★ 근접오류 | "아찔했던 순간" 회상 1컷 |
| ✕ 사건 | 화면 채도 0, 사건 개요 1문장, "무엇이 이 결과를 만들었을까요?" |

### 4.8 인과 회고
```
┌──────────────────────────┐
│ 어느 시점부터 방어막이      │
│ 약해졌다고 보시나요?        │
│ ○ 09:20 단독 진행 결정     │
│ ○ 09:40 브리핑 생략        │
│ ○ 10:05 동료확인 미수행    │
│ ○ 10:20 이상징후 후 계속   │
│ [ 내 생각 확인 ]           │
└──────────────────────────┘
```
- 개인을 정답/오답으로 판정하지 않는다.
- 실제 `breachChain`을 겹쳐 보여 조건의 누적과 방어막에 초점을 둔다.

### 4.9 Swiss Cheese 타임라인
```
09:20 단독 진행        ●───[ 감독 ]  🧀 구멍
09:40 브리핑 생략       ●───[ 브리핑 ] 🧀 구멍
10:05 Peer Check 미수행 ●───[ 동료확인 ] 🧀 구멍
10:20 이상 후 계속      ●───[ STOP ] 🧀 구멍
                        ▼
                 사건/근접오류 결과
```
- 각 행 탭 → 해설 + **[이 지점부터 리플레이]**

### 4.10 HP 리뷰
- 5대 학습행동 지표를 레이더 차트 + 수치로 표시
- 위험요인 ▲ 표시는 플레이 후에만 공개
- 개인 능력·적성·인사평가 지표가 아니라는 안내 상시 표시
- HP 획득 내역 분해 제공

### 4.11 실사건 공개
- "이 시나리오는 실제 원전에서 발생한 인적오류 사건을 재구성했습니다."
- 사건 개요(익명화) → 근본원인 → 기여요인 → 핵심 교훈(HU Tool)
- R2에서 다른 참가자 선택 분포 제공

### 4.12 리더보드
- 전체 / 우리 발전소 / 직무 필터
- 월별 시즌 선택, 지난 시즌 확정 순위 열람
- 닉네임·발전소·조직 직무·HP·순위만 노출
- 내 순위·상위% 하단 고정
- "순위는 학습 참여 지표이며 인사평가와 무관합니다" 고지
- 개인 5대 지표·선택내역·엔딩 미노출

### 4.13 내 기록
- 누적 HP 프로필 레이더 + 이번 시즌 학습경향
- 장별 최고 기록·플레이 횟수, 칭호/배지, 시즌 이력
- 닉네임 변경(활성 시즌당 1회)

### 4.13A 사운드 설정
```text
┌─────────────────────────────┐
│ 사운드 설정                 │
│ 음악        [ON]  ───●──    │

```
- 캠페인 맵의 설정 아이콘과 내 기록 메뉴에서 진입.
- BGM은 장면 전환 시 짧게 crossfade.
- 대사창이 열리면 BGM을 낮추고, 선택 확정 SFX는 짧고 중립적으로 사용.
- 엔딩 연출도 큰 경보음 대신 짧은 stinger + 시각 도장으로 전달.

## 6. 모션 원칙
- 지속시간: 마이크로 150ms, 화면 전환 250ms, 엔딩 연출 ≤ 1.5s
- `prefers-reduced-motion` 시 타이핑·흔들림·슬로모션 비활성
- 연출은 **탭으로 스킵 가능**
- 스킵 시 연결된 SFX도 즉시 종료/정리

## 7. 접근성
- **WCAG 2.2 AA** 목표
- 스크린리더: 선택지 `role="radiogroup"`, 대사창 `aria-live="polite"`
- 글자 크기 3단계
- 포커스 링 명확히 표시
- 오디오 없이도 모든 의미·상태·경고를 동일하게 이해 가능

## 8. 마이크로카피 원칙
- 평가·비난 어조 금지
- **"당신이 사고를 냈다" 같은 개인귀속 문구 금지**
- 안전 정지는 긍정적으로: "멈춘 것은 실패가 아닙니다"
- 현장 용어 우선, 영문 HU Tool명은 한글 병기

## 9. 아트·오디오 에셋 목록 (MVP)
| 종류 | 수량 | 사양 |
|---|---|---|
| 초상화 | 인물 6명 × 표정 3종 | WebP 512×640, 투명 배경 |
| 배경 | 정비작업장, 기기실, 주제어실, 사무실, 복도 | WebP 1080×810 |
| 카드 일러스트 | HU Tool 8종 | SVG 아이콘 |
| 엔딩 도장 | 4종 | SVG |
| 장 노드 아이콘 | 상태 4종 | SVG |
| BGM | 5개 기본 루프 + 3개 엔딩/스팅어 | MP3, instrumental, loop/short cue |
| SFX | 10~15개 | MP3, 0.1~2.5s, 실제 원전 경보음 유사성 금지 |

아트는 자체 제작 또는 상업 이용 가능한 생성 이미지로 제작하고, 실제 발전소 사진·로고는 사용하지 않는다. 오디오는 Google Flow Music/Lyria 등 생성 도구를 제작 단계에서 활용할 수 있으며, 실제 발전소 경보/설비음을 샘플링하지 않는다. 모든 오디오는 asset manifest와 검수기록을 남긴다.
