# PWA 배포 후 캐시 갱신 보완

2026-10-15 · 기존 운영 브라우저에서 배포 전환 중 빈 화면이 잠시 나타났고, 새 탭과 후속 새로고침에서 정상 표시를 확인했다. 이 현상의 원인을 특정하지는 않았다. 코드 점검에서 별도로 재현 가능한 두 가지 캐시 처리 문제를 보완했다.

## 변경

- 캐시된 파일을 먼저 반환해도 백그라운드 다운로드·캐시 기록이 끝날 때까지 `FetchEvent.waitUntil()`로 서비스워커의 작업 수명을 연장한다.
- JavaScript·CSS 요청에 서버의 HTTP 200 HTML 대체 페이지가 반환되면 캐시하지 않는다. 스크립트와 스타일은 각각 대응하는 MIME 형식을 확인한다.
- 같은 URL에 이미 잘못 저장된 HTML 응답이 있어도 실행 파일로 반환하지 않고 정상 네트워크 응답으로 복구한다.
- 설치 시 사전 저장하는 빌드 파일에도 같은 형식 검사를 적용한다.

외부 API·외부 SDK 요청은 가로채지 않는다. 캐시 이름, 저장된 오프라인 자산, 화면 이동의 네트워크 우선 방식과 계정·플레이 데이터 처리는 변경하지 않는다.

## 검증

`node --test scripts/service-worker-cache.test.mjs`는 실제 서비스워커 파일을 격리된 이벤트·캐시 환경에서 실행해 다음을 검사한다.

1. 캐시된 JS의 즉시 반환과 이벤트 수명에 연결된 백그라운드 갱신.
2. HTTP 200 HTML의 JS 캐시 유입 차단.
3. HTTP 200 HTML의 CSS 캐시 유입 차단.
4. 기존에 잘못 저장된 HTML을 정상 JS로 복구.
5. 오프라인에서 저장된 JS와 앱 셸 사용.
6. 외부 스크립트의 캐시·요청 개입 방지.

이 회귀 검사는 CI의 PWA 단계에도 포함한다. 브라우저별 서비스워커 수명 차이와 실제 망 전환 전체를 재현하는 검사는 아니며, 운영 전환 시 화면 표시 확인을 병행한다.

[첫 파일럿 참여코드와 진행 기록](72_S02_EXPLORATION_PARTICIPATION_CODES.md)은 별도 운영 문서로 유지한다.
