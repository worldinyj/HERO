## 1. 유지할 디자인

`docs/03_UXUI.md`의 '작전도 위의 하루'를 따른다. 배경 #0E1624, 패널 #16213A, 글자 #E8ECF4, 앰버 #F2A541을 유지한다. KHNP 공식 CI의 녹색·파란색은 로고에 적용하고 앱 전체 색을 바꾸지 않는다. 캐릭터는 무광 재질의 절제된 3D 일러스트로 제작한다. 귀여움은 둥근 형태와 부드러운 표정에서 만들고 성인 현장 학습에 어울리는 복장과 차분한 자세를 유지한다.

2026-10-12 선택 방향은 **B안 아기 수리**다. 최초 성체 수달의 사실적인 인상이 부담스럽다는 사용자 피드백을 반영해, 큰 둥근 머리·짧고 통통한 팔다리·작은 둥근 발·크림색 주둥이·부드러운 인형 질감으로 수정했다. 사용자는 수정 시안에 긍정적으로 응답했다. 긴 수염·사람 같은 손가락·긴 다리·세밀한 실제 털 표현을 줄이고, 흰 안전모·KHNP 마크·네이비 작업복·앰버 포인트를 유지한다. A안 및 성체 B안은 비교 이력으로만 남긴다.

## 3. 화면 적용

1. 로그인: HERO 제목과 짧은 소개 아래에 환영 캐릭터 1개. 카카오 버튼과 초대 안내는 유지한다.
2. 캠페인: 장별 작은 상황 그림으로 카드 구분. 캐릭터는 오늘의 학습 시작 안내에 사용한다.
3. 브리핑: 현장 배경 일러스트와 함께 상황을 소개한다. 실제 설비 배치·계기값·식별번호를 임의로 만들지 않는다.
4. 플레이: 작은 초상화와 대사창으로 설명 주체를 표시한다. 캐릭터의 표정·방향·효과가 선택의 정답이나 위험도를 미리 암시하지 않는다.
5. 결과·회고: 함께 타임라인을 살피는 차분한 포즈. 사건/근접오류 결과에서 웃음·엄지척·축포를 쓰지 않는다. 사용자를 비난하는 표정이나 '나쁜 작업자' 연출도 쓰지 않는다.
6. 관리자: 캐릭터는 빈 상태 안내에만 소형으로 사용하고 집계·오류 가독성을 우선한다.

## 4. KHNP 마크

공식 CI 출처: https://www.khnp.co.kr/main/contents.do?key=2238
시안 참고 이미지: https://www.khnp.co.kr/site/main/images/contents/cts86_img09.png

안전모의 작은 패치와 로그인 헤더의 독립 로고 영역을 비교한다. 생성 이미지의 로고는 배치 시안이며, 실제 구현에서는 공식 원본 파일을 별도 SVG/PNG 레이어로 사용해 형태·색상·비율을 보존한다. 캐릭터 가칭과 KHNP 공식 마스코트 명칭을 혼동시키지 않는다.

## 5. 최초 자산 범위

선택된 캐릭터의 환영·관찰·함께 확인·생각·회고·중립 포즈 6개, 로그인 메인 이미지 1개, 캠페인 상황 썸네일 3개를 우선 제작한다. 작은 화면에서도 읽히는 실루엣과 제한된 소품을 유지하고 투명 배경으로 앱에 배치한다. 캐릭터 이동·반복 점멸은 최소화하며 reduced-motion 설정을 따른다. 장식 이미지는 빈 alt, 실제 정보를 전달하는 그림은 별도 설명을 제공한다.

## 6. 이번 비교 이미지 브리프

각 안을 같은 네이비·앰버 배경과 같은 구도로 비교한다. 큰 전신 캐릭터, 모바일 로그인 적용 예시, 하단 환영·확인·회고 포즈를 보여준다. KHNP 공식 CI는 마크 참고 이미지로 사용한다. 긴 UI 텍스트보다 캐릭터·표정·배치 판단에 집중한다. 생성 시안은 콘셉트 선택용이며 아직 런타임 자산 경로를 변경하지 않는다.


## 7. 실제 화면별 적용 명세

현재 디자인 보드는 캐릭터와 모바일 화면의 방향을 보여주는 시안이다. 보드 전체를 한 장의 이미지로 앱에 넣지 않고, 독립 캐릭터 자산·별도 KHNP 로고·실제 텍스트와 버튼으로 구성한다.

| 화면 | 배치·역할 | 사용할 포즈 | 구현 연결 지점 |
|---|---|---|---|
| 로그인·초대 첫 화면 | HERO 제목과 짧은 소개 아래, 카카오 버튼 위에 배치. 초대 안내·약관 링크를 실제 텍스트로 유지 | 환영 | `features/auth/LoginPage.tsx`; 초대 화면은 구현 시 현재 모듈 확인 |
| 캠페인 홈 | 도입부의 작은 안내 캐릭터와 장별 상황 썸네일. 장 카드의 제목·진행 상태는 실제 텍스트로 표시 | 안내·중립 | `app/App.tsx`, `features/play/CompetitiveCampaignChapters.tsx` |
| 장 브리핑 | 상황 설명 옆 또는 위에 소형으로 배치. 이후 장별 배경 그림과 함께 사용 | 함께 확인 | `features/play/CompetitiveBriefingPage.tsx` |
| 플레이 | 대사창 옆의 작은 안내자 초상화. 실제 시나리오 발화자의 정체성을 바꾸지 않음. 질문·선택지·시계가 우선 | 중립·생각 | `features/play/SceneStage.tsx`, `features/play/components/PlayNodeStage.tsx` |
| 결과·회고 | 결과 내용과 방어막 타임라인 아래에 조용히 기록을 돌아보는 그림 | 회고 | `features/play/result/CausalReflection.tsx`, `HpReview.tsx` |
| 관리자 | 조회 결과가 없는 상태의 짧은 안내 옆에만 소형으로 배치. 권한 오류·서버 실패를 빈 결과와 혼동시키지 않음 | 중립 | 관리자 각 페이지의 empty state |

첫 단계는 **로그인 → 캠페인 → 브리핑**으로 정한다. 플레이·결과는 콘텐츠와 접근성을 함께 확인한 뒤 적용한다. 관리 화면은 마지막에 소형 자산을 재사용한다.

## 8. 제작할 독립 이미지와 공통 컴포넌트

### 8.1 1차 범위

아기 수리 마스터 디자인 1개를 고정하고 동일한 얼굴·머리/몸 비율·복장으로 환영, 함께 확인, 회고 **3포즈**를 먼저 만든다. 화면 크기에 맞는 전신·상반신 출력은 같은 디자인에서 파생한다. 정사각형 또는 세로형 **진짜 투명 배경** PNG 마스터와 웹용 WebP를 준비한다. 기존 보드 내 작은 포즈를 잘라서 최종 자산으로 사용하지 않는다.

계획 경로:

- `apps/web/public/images/mascot/suri-welcome-v1.webp`
- `apps/web/public/images/mascot/suri-check-v1.webp`
- `apps/web/public/images/mascot/suri-reflect-v1.webp`
- `apps/web/public/images/brand/khnp-signature.png` (공식 원본)
- `apps/web/src/components/SuriIllustration.tsx` (공통 표시)
- `apps/web/src/components/KhnpBrand.tsx` (독립 로고 표시)

위 파일과 컴포넌트는 **제작·저장 완료**했다. 로그인 화면에 환영 포즈와 독립 공식 로고를 연결했다. 함께 확인·회고 포즈의 화면 연결은 후속 단계다. 로고 마크·문구·카카오 버튼은 각각 별도 레이어로 구성한다. 안전모 패치는 생성 그림의 일부이며, 앱의 기관 표시는 변형하지 않은 공식 원본을 별도로 사용한다.

### 8.2 크기·성능·접근성 목표

- 로그인 캐릭터는 모바일에서 대략 140~180px 폭으로 시작하고 실제 360×800/390×844에서 버튼 위치·전체 높이를 조정한다. 데스크톱은 약 220~260px 폭.
- 플레이 초상화는 48~64px로 제한해 선택지와 시계를 가리지 않는다. 관리 빈 상태는 64~96px 수준.
- 기존 480px 콘텐츠 폭과 네이비/앰버 대비를 유지한다. 시안의 긴 장식 문구를 그대로 UI에 옮기지 않는다.
- 로그인 이미지는 빠르게 읽고 이후 화면 자산은 필요한 때 로드한다. 고해상도 보드 원본을 런타임에서 다운로드하지 않는다. 웹 자산별 100~180KB, 로그인에서 추가되는 이미지 총량 250KB 이하를 초기 목표로 두고 화질과 실측으로 조정한다.
- width/height 또는 aspect-ratio를 지정해 로딩 중 화면이 밀리지 않게 한다. 로딩 실패 시 초대·로그인·학습 행동을 계속 사용할 수 있게 한다.
- 버튼·대사·주의사항은 읽을 수 있는 실제 HTML 텍스트로 유지한다. 장식 캐릭터에는 빈 alt, KHNP 로고에는 적절한 이름을 제공한다.
- 초기에는 정적 이미지로 적용한다. 애니메이션은 필요가 확인될 때 짧은 진입 정도만 추가하고 reduced-motion을 따른다.

## 9. 적용·검증·운영 반영 순서

1. **디자인 기준 고정:** 선택된 아기 수리 시안을 얼굴·비율·팔레트·복장 기준으로 사용한다.
2. **자산 제작:** 1차 3포즈와 웹 출력, 공식 CI 원본을 준비한다. 작은 크기에서도 수달로 읽히는 얼굴·꼬리와 포즈 일관성을 확인한다.
3. **브랜치 구현:** 공통 컴포넌트와 로그인·캠페인·브리핑에 우선 연결한다. 구현 시작 전 main 및 PR #99의 최종 상태를 다시 확인해 최신 관리자 변경과 충돌을 피한다.
4. **미리보기 확인:** 360×800/390×844, PC에서 잘림·가로 넘침·카카오 버튼·한글 줄바꿈·키보드 초점을 확인한다. 초대/로그인 동작, 이미지 오류·저속 로딩, 현재 JS 분할·번들 제한이 유지되는지 검증한다.
5. **회고 화면 확장:** 사건/근접오류에서 표정이 축하·비난으로 읽히지 않는지, 시나리오의 실제 대사 주체가 바뀌지 않는지 확인한다.
6. **운영 반영:** 화면 검토 후 변경 범위를 PR로 정리하고 필요한 검사 후 병합·기존 Cloudflare 배포 절차·운영 파일 일치와 주요 경로 확인을 수행한다. 현재 로그인 시범 구현은 디자인 브랜치에만 저장한다. 기존 사용자 요청에 따라 GitHub Actions는 실행하지 않는다.
