## 구현 결과

- 환영·함께 확인·회고 PNG 원본 3개와 웹용 WebP 3개를 저장했다. PNG 원본은 웹 공개 폴더 밖에서 관리한다.
- `LoginPage.tsx`에서 카카오 버튼 위에 환영 수리를 배치했다. 모바일 폭 176px, 640px 이상 화면 폭 220px로 표시한다.
- KHNP 공식 CI 원본은 독립 `KhnpBrand` 컴포넌트로 표시한다. 로고의 형태와 색을 바꾸지 않는다.
- 제목은 “함께 확인하고, 함께 배웁니다.”이며 초대 안내·평가와 무관하다는 안내·정책 링크를 유지했다.
- `SuriIllustration`은 장식 이미지로 빈 alt를 제공하고 크기를 예약한다. 로그인에서만 즉시 로드하고 나머지 포즈는 필요할 때 지연 로드한다. 이미지 실패 시 로그인 버튼을 계속 사용할 수 있다.
- 카카오 로그인 핸들러, 안전한 복귀 경로, 초대 필요 안내, 요청 중 버튼 비활성화, 오류 표시는 기존 동작을 유지한다.

## 자산 검증

6개 자산 모두 원본 SHA-256·Git blob SHA·픽셀 크기·바이트 수를 대조했다. PNG와 WebP의 실제 알파 채널 및 투명 모서리를 확인했다. KHNP 로고는 136×29 RGBA 원본이다. 환영 WebP 55,942바이트와 로고 4,319바이트를 합쳐 첫 화면의 추가 이미지 용량은 60,261바이트(약 58.9KiB)다.

## 최초 디자인 브랜치 검증의 제한

현재 환경에는 지원되는 브라우저 검증 기능이 없어 모바일 브라우저 QA와 실카카오 OAuth를 실행하지 않았다. 대화의 화면 미리보기는 배치를 확인하기 위한 시안이며 실제 브라우저 검사 결과가 아니다.

후속 검토에서는 `/login`과 `/login?reason=invite_required`를 360×800·390×844·PC에서 확인한다. 캐릭터 잘림·가로 넘침·초대 안내 줄바꿈·카카오 버튼 위치·키보드 초점과 약관 링크를 확인하고, 이미지 차단 시에도 로그인 행동이 가능해야 한다. OAuth 완료 후 기존 복귀 경로가 유지되는지 확인한다.

## 후속 범위

먼저 로그인 화면의 실제 느낌을 검토한 뒤 캠페인·브리핑에 함께 확인 포즈를 연결하고 회고 화면을 확장한다. 이번 시범 적용은 디자인 브랜치에만 저장하며 main 병합·운영 배포는 하지 않았다. GitHub Actions는 기존 사용자 요청에 따라 실행하지 않았다.

## 최신 main 통합 검증 (2026-10-12)

관리자 운영 현황(PR #99)을 포함한 main 위에 디자인 브랜치를 충돌 없이 통합했다. 환영 수리를 로그인에 적용하고, 함께 확인·회고 포즈는 자산만 저장한다. 원본 디자인 브랜치와 자산 바이트는 보존한다.

- 단위 테스트 375개, 전체 typecheck/lint/build, 초기 JS 예산, route splitting, client secrets, social metadata 통과.
- 추가 브라우저 테스트 8개 통과: 360×800·390×844·1280×900, 일반 로그인·초대 필요 안내, 이미지 디코딩, 가로 넘침, axe 접근성, 키보드 정책 링크 이동, 이미지 차단 및 로그인 오류 후 버튼 복구.
- 모바일·PC 전체 화면 캡처를 육안 검토했다. 로그인에서는 함께 확인·회고 이미지를 요청하지 않는다.
- 원본·웹용·로고 7개 파일의 바이트 수 및 SHA-256을 기존 자산 manifest와 대조했다.
- 브라우저 검증은 로컬 E2E 모드이다. 실제 카카오 OAuth 왕복 및 실기기 검증은 실행하지 않았다. 기존 인증 회귀 검사는 전체 CI에서 확인한다.

## 브리핑·회고 확장 (2026-10-12)

- 준비된 함께 확인 포즈를 유효한 장 브리핑 제목 옆에 표시한다. 로딩·열리지 않은 장·권한 제한 화면에는 표시하지 않는다.
- 회고 포즈는 튜토리얼과 경쟁 플레이가 공유하는 인과 회고 화면에 표시한다. 진행 중 판단 화면이나 결과별 축하·비난 표현은 추가하지 않는다.
- 모바일 80px·640px 이상 112px, 예약된 정사각형 영역, 장식용 빈 alt, 지연 로딩을 사용한다. 이미지 실패 시 제목·선택지·진행 버튼을 유지한다. 기존 콘텐츠·점수·인증·오디오 처리 변경은 없다.
- 기존 나레이션 모바일 검사를 확장해 정상 이미지·WCAG 2.2 AA·가로 넘침과 이미지 차단 후 브리핑→플레이→회고→타임라인 진행을 검증한다. 모바일·PC 캡처도 검토한다.
