## 1. 제품 비전

원전 종사자가 **결과를 모르는 사건 발생 이전 시점**에 서서, 제한된 정보·시간 압박·조직 분위기 속에서 판단하고, 작은 판단들이 연결되어 사건이 되는 과정(Swiss Cheese)을 **직접 체험**하게 하는 모바일 우선 시뮬레이션 게임.

> 목표 학습 효과: *"나라면 저렇게 하지 않았을 텐데"* → *"나도 저 상황이라면 그렇게 했을 수 있겠다"*

## 3. 대상 사용자 (Persona)

### 3.1 권한 계층

```
관리자(Super Admin, 본사/교육원)
  └─ 발전소담당자(Plant Manager, 발전소별 교육담당)
        └─ 사용자(Player)
              ├─ SRO  (발전팀장/선임원자로운전원)
              ├─ RO   (원자로운전원)
              ├─ 현장운전원 (Field/Local Operator)
              ├─ 감독 (작업감독자/작업책임자)
              └─ 작업자 (정비·시험 작업자, 협력사 포함)
```

| 역할 | 주요 니즈 | 핵심 기능 |
|---|---|---|
| 관리자 | 전사 운영, 콘텐츠 품질 | 발전소·담당자 생성, 시나리오 승인·배포, 시즌 운영, 전사 통계 |
| 발전소담당자 | 소속 인원 참여 관리 | 사용자 초대, 참여 현황, 발전소 리더보드, 교육 캠페인 지정 |
| 사용자 | 짧은 시간에 재미있게 학습 | 시나리오 플레이, 리플레이, 내 HP 프로필, 리더보드 순위 |

### 3.2 직무(job_role)와 플레이 관점(perspective_role)의 구분
- `job_role`은 사용자의 **조직상 직무**(SRO/RO/현장운전원/감독/작업자)이며, 발전소 운영·통계와 직무별 리더보드 필터에 사용한다.
- MVP에서는 **모든 사용자가 동일한 3개 시나리오를 동일한 고정 관점(perspective_role)으로 플레이**한다. 따라서 전체 리더보드에서 비교 가능한 문제 수와 점수 기회를 동일하게 유지한다.
- 같은 사건을 RO 시점·작업자 시점 등으로 다르게 플레이하는 **다중 관점 모드**는 Release 2 이후 기능(F-PLAY-10)으로 둔다. 이때도 동일 관점끼리의 별도 랭킹 또는 정규화 점수만 비교한다.

## 4. 핵심 설계 원칙

1. **Hidden Hazard** — Hazard Index 수치를 플레이 중 노출하지 않는다. 상황 묘사·동료 반응·지시값 변화로만 암시.
2. **정답 없는 선택지** — 모든 선택지는 현장에서 실제로 할 법한 합리적 행동. "절차 준수 vs 무시" 같은 이분법 금지.
3. **정보 획득도 선택** — 절차서 확인·동료 질문·주제어실 연락은 시간(턴)을 소비한다. *속도 vs 확인*의 긴장.
4. **Swiss Cheese** — 단일 실수로 사건이 나지 않는다. 방어막(HU Tool)이 연속 붕괴할 때만 사건 발생.
5. **학습 > 평가** — 결과는 개인 인사평가·징계에 사용하지 않는다(이용약관·화면에 명시). 리더보드는 **학습 행동**을 보상한다(§7).
6. **사람의 마지막 행동을 원인으로 끝내지 않음** — 개인의 오류행동은 사건 흐름의 한 요소로 다루고, 시간압박·절차/설계·감독·의사소통·조직조건·방어막까지 함께 분석한다.
7. **실사건 기반·익명화** — OPIS 사건을 재구성하되 발전소명·호기·설비번호·세부 운전값·개인식별정보는 교육 목적에 필요한 수준으로 가상화·일반화한다.
8. **교육용 모델의 한계 명시** — 게임의 Hidden Hazard Index와 PSF 가중치는 학습용 상대지수이며 실제 HRA 확률, 설비 위험도, 종사자 능력평가 값으로 해석하지 않는다.
9. **오디오는 보조 정보** — 핵심 판단정보는 소리에만 의존하지 않는다. 실제 원전 경보음·설비음과 혼동 가능한 SFX는 금지하고, BGM/SFX는 독립 음소거·볼륨 조절을 제공한다.

## 5. 게임 콘셉트 — "공명전식" 연출 적용

삼국지 공명전(코에이)의 **장(章) 구성 캠페인 + 초상화 대화 + 전장 판단 + 책략** 구조를 **장르 차원에서 차용**한다. 원작의 캐릭터·그래픽·명칭·음악 등 IP는 일절 사용하지 않는다.

| 공명전 요소 | HERO 대응 | 교육적 의미 |
|---|---|---|
| 장(章) 단위 캠페인, 지도 위 진행 | **발전소 캠페인 맵** — 사건 1개 = 1장 | 학습 경로 가시화 |
| 초상화 + 대사창 (비주얼노벨) | 동료·팀장·주제어실 인물의 대화 컷 | 조직 분위기·압박 전달 |
| 전장 판단 (턴 진행) | **작업 타임라인** — 턴마다 시계가 흐름 | 시간 압박 체험 |
| 책략(계략) 카드 | **방어막 카드(HU Tool)** — Peer Check, Three-way Comm. 등 | 도구 사용의 효과 체험 |
| 장수 능력치·성장 | 플레이어 **HP 프로필 5대 지표**, 칭호 | 강점/약점 인식 |
| 전투 후 공적 평가 | **Human Performance Review** + 사건 공개 | 성찰 |
| 분기 엔딩 | 사건 발생 / 근접오류 / 무사고 완료 엔딩 | 다중 결과 체험 |

### 5.1 방어막 카드 시스템 (책략)
- 시나리오 시작 시 상황에 맞는 **카드 3~5장**을 손패로 받는다 (예: Pre-job Briefing, Peer Check, Self Check(STAR), Three-way Communication, Stop When Unsure, Place Keeping, Independent Verification, Questioning Attitude).
- 카드 사용은 **턴(시간)을 소모**하며, 숨겨진 Barrier 값을 올린다.
- 카드를 언제 쓰느냐가 핵심 — "아무 때나 다 쓰기"가 최적이 되지 않도록 시간 비용과 상황 적합성을 부여(LOOP 담당 밸런스).

### 5.2 엔딩 등급
| 엔딩 | 조건 | 연출 |
|---|---|---|
| ★★★ 무사고 완수 | 위험 임계 미도달 + 일정 내 완료 | 정상 완료, 팀장 칭찬 |
| ★★ 안전 정지 | Stop When Unsure 등으로 중단, 일정 지연 | "지연은 사건이 아니다" 메시지 |
| ★ 근접오류(Near Miss) | 임계 근접, 마지막 방어막이 차단 | 아찔한 순간 회상 |
| ✕ 사건 발생 | 방어막 연속 붕괴 | 절제된 연출, 사건 분석으로 연결 |

## 7. 리더보드 점수 설계 — "HP Point"

리더보드는 **안전성과 학습 참여를 촉진하되, 운·직무별 콘텐츠 수·반복 파밍이 순위를 좌우하지 않도록** 설계한다. MVP에서는 모든 사용자에게 동일한 시나리오 3종과 동일한 고정 관점을 제공한다.

### 7.1 시나리오 점수
한 번의 완료 세션에 대해 서버가 아래를 계산하고, 시즌 순위에는 **시나리오별 최고 점수 1개만** 반영한다.

| 구성 | 산정 | 최대 | 의도 |
|---|---:|---:|---|
| 완주 | 완료 세션 +100 | 100 | 참여 보상 |
| 엔딩 | 무사고 +60 / 안전정지 +55 / 근접오류 +35 / 사건 +15 | 60 | 안전정지를 실패로 취급하지 않음 |
| 학습행동 지표 | 5대 지표 평균 | 100 | 판단 과정의 질 |
| 인과 회고 | 회고 응답 +10, Swiss Cheese 해설 확인 +10 | 20 | 정답 맞히기가 아닌 성찰 보상 |
| 리플레이 개선 | 이전 최고 지표 대비 개선분 × 0.5 | 30 | 반복 학습 보상, 상한 적용 |

- **시나리오 HP 최대 = 310점**. 세부 계수는 밸런스 테스트 후 조정 가능하되, 변경 시 `score_rule_version`을 기록한다.
- 선택지·카드 효과와 이벤트 판정은 서버에서 같은 엔진으로 재계산한다. 클라이언트가 보낸 점수는 신뢰하지 않는다.
- 확률 구간이 있는 경우 **같은 시즌·같은 시나리오는 동일 simulation seed**를 사용하여 참가자 간 운 차이를 제거한다. 선택지 표시 순서는 별도 presentation seed로 섞을 수 있다.
- 시즌 점수 = `Σ(시나리오별 최고 HP)`. 무한 반복, 플레이 횟수 자체, 접속시간은 점수에 직접 가산하지 않는다.
- 시즌 종료 시 스냅샷을 확정한다. 누적 리더보드·포상 CSV는 Release 2에서 제공한다.

> **운영 원칙**: HERO의 플레이 결과·HP 지표·순위는 학습과 참여를 위한 것이며 인사평가·징계에 사용하지 않는다. 발전소담당자는 개인별 점수·선택·5대 지표를 조회할 수 없고, 참여/완료 현황과 익명 집계만 본다.

## 8. 콘텐츠 전략 — OPIS 기반

### 8.1 소스
- **OPIS(원전안전운영정보시스템, opis.kins.re.kr)** 의 사건·고장 정보 및 사건조사보고서 PDF.
- OPIS 공개 사건·고장 자료 중 **인적행위가 직접원인·근본원인·기여요인 또는 방어막 실패와 관련된 사건**을 후보로 선별한다. 단, “작업자 실수”만으로 설명을 끝내지 않고 사건조건과 조직·절차·설계·감독 요인을 함께 재구성한다.

### 8.2 선별 기준 (SAGE)
| 기준 | 설명 |
|---|---|
| 의사결정 지점 | 작업자 판단이 개입한 지점이 3개 이상 식별 가능 |
| 오류 유형 다양성 | 설비 오인, 절차 미준수, 의사소통, 확인 누락, 감독 부족 등 균형 |
| 직무 커버리지 | SRO/RO/현장운전원/감독/작업자 시점이 고르게 분포 |
| 교육 적합성 | 설비 세부 운전값 없이도 HP 교훈이 성립 |
| 공개 적합성 | 익명화·일반화 후 민감정보·보안정보·실제 운전절차 상세가 노출되지 않음 |
| 시스템적 학습성 | 개인의 마지막 행동을 넘어 PSF·절차·감독·설계·조직조건·방어막을 설명할 수 있음 |

### 8.3 파이프라인
```
OPIS PDF 수동 수집(관리자) → 업로드 → 텍스트 추출
 → [SAGE] AI 분석: Timeline · **Direct Cause · Root Cause · Contributing Cause/Factor** · PSF · Error Precursor · Barrier
 → [STORY] Scene 구성 · 대사 · 익명화
 → [LOOP] 선택지·리스크 가중치·카드·엔딩
 → Human Factor 전문가 검토/서명 → 승인 → 배포
```
- **AI는 제작 도구로만 사용** (플레이 중 실시간 생성 금지 — 교육 일관성·검증성 확보).
- OPIS 자료의 이용조건(저작권·공공누리 유형)을 확인 후 사용. 자동 대량 크롤링은 하지 않고, 필요한 보고서만 관리자가 수집한다.

### 8.4 MVP 시나리오 3종
| # | 제목 | 주제 | 주 시점 |
|---|---|---|---|
| S01 | "오늘 오전까지 끝내야 합니다" | 시간압박·단독작업·감독부족 | 고정 관점: 작업자 |
| S02 | "아마 이 설비가 맞을 겁니다" | 설비 오인·Self/Peer Check | 고정 관점: 현장운전원 |
| S03 | "절차와 실제 상황이 조금 다릅니다" | 절차 준수·Questioning Attitude·Stop When Unsure | 고정 관점: RO |

각 시나리오는 OPIS 실사건 1건 이상을 근거로 재구성하고, 근거 사건 ID는 내부 메타데이터에만 기록한다. **MVP에서는 사용자 조직 직무와 무관하게 세 시나리오 모두 플레이 가능**하다.

| PSF | Performance Shaping Factor, 수행영향인자 (SPAR-H 참조) |
| HU Tool | Human Performance Tool, 인적오류 예방기법 |
| Barrier | 오류가 사건으로 진행하는 것을 막는 방어막 |
| HP Point | 리더보드 점수. 시즌 내 시나리오별 최고 학습점수의 합 |
| perspective_role | 특정 시나리오에서 플레이어가 맡는 관점/역할. 조직 직무(job_role)와 구분 |
| Hazard Index | 게임 내부 교육용 상대 위험지수. 실제 HRA 확률이 아님 |
| OPIS | 원자력안전기술원 원전안전운영정보시스템 |
| MCR | Main Control Room, 주제어실 |
