# 활성 시즌 시나리오 연결 관리

2026-10-11

시나리오를 배포 상태로 바꾸어도 활성 시즌에 연결되지 않으면 새 경쟁 플레이가 열리지 않았다. 관리자 화면에서 현재 시즌·배포 버전·연결 이력과 실제 플레이 가능 조건을 확인하고, 현재 배포 버전 연결 또는 연결 해제를 명시적으로 확인할 수 있도록 추가했다.

## 동작

- 현재 시간 범위 안의 열린 시즌을 표시한다. 시즌 없음·경쟁 시나리오 없음·조회 실패도 각각 안내한다.
- 활성 경쟁 시나리오의 현재 배포 버전만 연결한다. 기존 배포에서 보관으로 바뀐 연결은 실제 플레이 불가 상태로 표시한다. 이미 적용된 버전은 중복 연결 버튼을 비활성화한다.
- 확인창에서 시즌·시나리오·버전·기존 연결·영향을 보여준다. 취소와 Escape는 쓰기를 하지 않으며, 실행 중 중복 요청과 닫기를 차단한다.
- 성공 응답은 정확한 시즌·시나리오·버전·활성 플래그를 대조한다. 오래된 연결, 종료된 시즌, 불확실한 응답은 새로고침으로 확인하도록 안내하고 자동 재시도하지 않는다.
- 읽기 전용 조회와 변경은 관리자 인증을 거친 `admin-scenario` Edge에서 service-role 전용 RPC를 호출한다. 브라우저의 기존 무감사 일괄 동기화 RPC 권한은 철회한다. 월별 cron 동작은 유지한다.
- 변경 RPC는 상태 변경과 동일한 시나리오 부모 잠금, 시즌 잠금을 잡고 최신 시즌·배포 상태·기존 연결 지문을 다시 확인한다. 다른 연결 비활성화·선택 연결 활성화·감사 기록은 한 트랜잭션이며 실패 시 롤백한다.
- 기존 연결 행과 실행 seed는 보존한다. 연결 해제·재연결은 시작된 플레이, 학습기록, HP, 순위 또는 시나리오의 배포 상태를 수정하지 않는다. 새 연결에만 무작위 seed를 만든다. 화면에는 seed 값을 노출하지 않는다.

## 검증

- TypeScript, ESLint, Deno, 빌드, 공유 메타데이터, 초기 JS 크기 한도, 정적 DB 계약 통과.
- 단위 검증 349개(엔진 19 + 웹 330), 두 모바일 크기에서 시나리오 미리보기·비교·상태·시즌 연결 E2E 62개 통과. 새 연결 UI 20개 포함. 접근성 axe 검사 통과. 웹 응답은 로컬 fixture다.
- 새 pgTAP 46개 통과: 실행 권한, 비활성 관리자, 종료·예정·만료 시즌, 미배포·다른 시나리오·튜토리얼·비활성 시나리오, 이전 연결 지문, 감사 실패 롤백, 중복 요청, seed·연결 행 보존, 진행 중 플레이의 모든 필드 보존 포함. 기존 로컬 개발 DB에서 시험 트랜잭션 전체를 롤백했다.
- 별도 로컬 시험 DB에서 실제 두 연결 경합 검증: 같은 연결의 두 번째 오래된 요청은 거절하며, 먼저 보관한 버전은 대기하던 연결 요청이 활성화하지 못한다. 잠금 대기와 최종 연결·감사 수를 확인했다.

## 적용 순서

전체 CI 통과 후 신규 migration 027 → admin-scenario Edge → 웹 순서로 수동 운영 배포한다. 운영의 기존 마이그레이션 식별자 차이를 건드리지 않고 신규 SQL과 이력만 함께 기록한다. 실제 운영 시나리오 연결·해제는 검증 목적으로 실행하지 않는다.
