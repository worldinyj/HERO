# 이전 세션 재검토와 리더보드 조회 복구

2026-10-15 한국 시간. 기능 기준선은 main `17211b0` (PR #138)이다.

## 재개 지점

「이전 세션 작업 이어서 진행」의 마지막 완료는 참여자 제출 모듈을 초기 앱 묶음 밖으로 분리한 작업이다. 그 다음 메시지는 workspace routing 401 오류로 실행되지 않았다. 이 오류로 미완성 코드가 남은 것은 아니다. main에 해당 커밋과 문서 84번이 존재한다.

「히어로 게임 개발 방향 검토」의 탐색형 아이디어는 이미 S02 체험으로 구현됐다. 두 참여자의 체험 완료·현재 보고된 진행 문제 없음은 사용자 확인에 근거하며 상세 의견 원본은 대기 중이다. [71번 운영 기록](71_S02_EXPLORATION_PILOT.md)과 [72번 참여 기록](72_S02_EXPLORATION_PARTICIPATION_CODES.md)을 따른다. 경쟁판 완료나 실제 교육 효과로 집계하지 않는다.

10월 13일 감사의 83.7%는 고정된 과거 구현관리 지표다. 전체 86개 작업을 새로 감사하지 않았으므로 새 진척률을 만들지 않았다. 현황 안내와 readiness의 오래된 S01/S02 source hold·S03 게시 대기 표현은 현재 승인·운영 기록에 맞췄다. 기존 미커밋 밸런스 보고서·S03 파일럿 초안·오디오 후보 폴더의 설치파일은 이번 변경에 포함하지 않는다.

GitHub 열린 PR 조회에서는 #114(관리자 담당자 서버 검색·페이지 처리), #87(담당자 초대 입력 검증)이 남아 있다. 이 조회만으로 현재 main과의 중복·충돌·병합 준비를 판정하지 않았다. 같은 기능을 새로 만들기 전에 기존 PR을 검토한다.

## 이번 구현

리더보드의 시즌·첫 순위·내 순위·추가 페이지 조회에는 대기 제한이 없었다. API 실패에도 ‘아직 순위가 없습니다’가 표시됐으며, 추가 조회 오류 뒤 관찰자가 다시 조회할 수 있었다. 기존 문자열 query key는 전체 → 다른 범위 → 전체로 돌아온 경우 예전 추가 페이지 응답을 구분하지 못했다.

- 기존 `readWithDeadline`으로 읽기 요청을 15초 후 종료하고, 시즌·순위·추가 페이지별 수동 재시도를 제공한다.
- 오류·시즌 없음·성공했지만 순위 없음 상태를 구분한다.
- 추가 페이지 오류 때 기존 목록과 내 순위를 유지하고 자동 조회를 멈춘다. 사용자가 같은 offset을 다시 요청한다.
- 요청마다 증가하는 revision으로 같은 시즌·범위에 복귀해도 이전 요청을 구분한다. 범위·시즌 변경과 화면 이탈은 전송 취소 및 늦은 성공·실패 무시로 처리한다.
- 동시에 같은 페이지를 요청하는 것을 ref로 막는다. 공개 뷰·필터·HP 계산·DB·권한·승인 본문은 바꾸지 않는다.

## 검증

- 360×800·390×844 모바일 20건 통과: 시즌·첫 순위·내 순위 지연 종료/재시도, 진행·종료 시즌의 추가 조회 복구, 같은 범위·시즌 복귀 후 늦은 응답 배제, 오류와 빈 결과 구분.
- 기존 읽기 제한·요청 revision 단위 검사 9건 통과.
- 오류 화면 axe 접근성 위반 0, 360px·390px 가로 넘침 없음, 캡처 직접 확인.
- lint·TypeScript·프로덕션 빌드·초기 용량·경로 분리·클라이언트 비밀정보·사람 검토·승인 해시·TASKLIST 정적 무결성 통과.
- 초기 필수 JS 514,883 B / gzip 149,338 B로 기존 용량 상한 이내. Vite의 500kB chunk 권고 경고는 기존과 같이 남는다.

모의 API·Chromium 모바일 뷰포트 검사는 실제 참여자의 기록을 읽거나 생성하지 않으며 실기기 승인을 대신하지 않는다. 전체 DB·모바일 통합 CI를 이번 세션에서 재실행한 것으로 기록하지 않는다. 이번 변경은 `codex/resume-leaderboard-recovery` 브랜치에 저장하며 원격 PR·운영 배포는 아직 진행하지 않았다.

## 권장 후속 순서

1. 이번 조회 복구를 검증하고 배포한다. 두 체험자의 상세 의견과 본인 계정의 경쟁판 완료 → 서버 검증 → 내 기록·회고 재조회 결과를 접수한다. 접수 전에는 실제 이용 통과로 기록하지 않는다.
2. 접수된 진행 차단 문제부터 수정한다. 관리자 담당자 검색·초대 입력은 기존 PR #114·#87을 검토한 뒤 중복 여부와 적용 범위를 정한다.
3. 실제 기기 4종과 오디오·백그라운드 복귀·사내망 접근을 확인하고, 운영주체·보유기간 등 법무/개인정보 확정 사항을 수집한다.
4. 사업소 1곳 30명 이상 파일럿을 운영하고 완료율·리플레이·전후 질문·Blocker를 실제 결과로 집계한다. 로컬 미추적 파일 `docs/67_S03_PILOT_PLAN.md`의 계획 초안은 담당 일정·참여자 확정 후 사용한다.
5. 전용 staging과 같은 SHA의 Smoke/RC 및 실제 승인 근거가 모두 갖춰지면 정식 v1.0을 판정한다. 새 유료 프로젝트·DB 브랜치 생성은 기존 staging 격리 정책과 사용자 승인 범위를 확인한 뒤 진행한다.
6. 이동·애니메이션·Godot 확대는 탐색형 상세 의견을 보고 결정한다. 현재 승인 본문을 바꾸면 새 버전 검토를 거친다.
