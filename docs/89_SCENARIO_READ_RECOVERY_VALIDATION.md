# 관리자 시나리오 조회 지연 복구

2026-10-16. 운영 현황·감사 이력 조회 복구 PR #141 다음으로 시나리오 관리의 읽기 흐름을 점검했다. 목록·저장된 미리보기·버전 비교·검토 대상 확인·활성 시즌 조회에 응답 대기 제한이 없어 조회 작업이 계속 잠길 수 있었다.

## 변경과 경계

`list`, `preview`, `season-overview`를 명시적인 읽기 함수로 분리하고 기존 공통 15초 제한을 적용한다. 오류·지연 후에는 목록/시즌 새로고침이나 미리보기/비교/검토 확인 버튼으로 수동 재시도한다. 자동 재시도는 없다. 취소·대체 조회·대상 변경·화면 이탈 시 해당 읽기를 중단하고 기존 revision으로 늦은 결과를 무시한다. 비교의 두 저장 버전은 병렬로 읽으며 한쪽 실패 뒤 다른 읽기도 취소한다.

목록 응답은 명시적인 `versions` 배열과 고유 ID·양의 버전 번호·알려진 상태·유효한 시각·단일 시나리오 연결을 검증한다. 누락·오류·잘못된 응답은 ‘저장된 버전 없음’으로 처리하지 않는다. 새 조회 시 예전 버전과 상태 변경 버튼을 숨기고, 검토·비교 패널에도 조회 중/조회 실패를 구분해 표시한다. 버전 건수는 확인되지 않았으면 ‘미확인’으로 안내한다. 목록 API가 전체 건수를 제공하거나 서버 페이지 처리를 하도록 바꾸는 작업은 이번 범위가 아니다.

미리보기의 기존 스키마·그래프·버전 ID/번호 검증을 유지하고 목록의 시나리오 slug도 대조한다. 검토 대상의 내용 해시 확인 및 다운로드 잠금은 유지한다. 목록을 다시 읽는 동안 확인 상태는 무효화하지만 작성 중인 검토 문구는 보존한다. 비교는 기존처럼 클릭 시점 JSON 사본을 기준으로 하며 승인이나 게시를 기록하지 않는다.

`upload`, `set-status`, `set-season-scenario`는 기존 쓰기 호출과 정확한 응답 확인·명시적 확인 창을 유지한다. 읽기 제한이나 읽기 취소 신호를 쓰기에 전달하지 않는다. 쓰기 성공 후 재조회에 실패하면 읽기만 다시 요청하며, 쓰기를 자동으로 반복하지 않는다. DB·권한·승인 본문·시즌 구성·실제 운영 기록은 이 구현에서 변경하지 않는다.

## 검증

기존 모바일 회귀 86건과 신규 읽기 복구·쓰기 경계 24건을 확인했다. 신규 검사에서 쓰기 요청 수신과 후속 읽기 시작을 구분해 기다린 뒤 가상 시간을 진행하도록 보완했으며 최종 신규 24건이 통과했다. 기존 취소 검사는 실제 전송 중단을 확인하도록 갱신했다. 전체 단위 460건, lint·TypeScript·프로덕션 빌드·초기 JS 예산·경로 분리·클라이언트 비밀정보 검사가 통과했다. 목록 오류 화면 axe 위반 0·가로 넘침 없음을 확인하고 캡처를 검토했다.

- 응답 검증 단위 13건: 명시적인 빈 배열·객체/배열 join, 누락 목록·서버 오류·중복 ID·잘못된 버전/상태/시각·불명확한 시나리오 연결 거부.
- 신규 모바일 360×800·390×844 읽기 복구 검사: 목록·미리보기·비교·검토·시즌 지연 후 수동 복구, 잘못된 목록 응답, 늦은 응답 배제, 작성 중 검토 문구 보존.
- 쓰기 요청 3종은 15초가 지나도 대기·확인 상태를 유지하고 1회만 전송한다. 상태/시즌 변경 성공 후 재조회 지연도 쓰기를 재전송하지 않는다. 모두 로컬 모의 응답으로 검사하며 실제 운영 변경을 하지 않는다.
- 기존 미리보기·HTO 시안·버전 비교·검토 결과·상태 변경 확인·시즌 연결 검사를 함께 실행한다. 오류 화면 axe·가로 넘침·캡처를 확인한다.

최종 자동 검사 건수·CI·병합·운영 파일 대조 결과는 해당 PR에 기록한다. 기반 사건은 S01·S02·S03의 3건으로 유지된다. 체험자 상세 의견과 실제 경쟁판 완료·서버 검증·내 기록 반영 결과, 정식 출시의 별도 사람/외부 근거는 이 자동 검사로 대체하지 않는다.
