# 관리자 운영 현황 요약

활성 관리자 계정으로 `/admin/overview` 또는 관리자 메뉴의 **운영 현황**에 접속한다.

## 표시 항목

| 항목 | 정의 |
|---|---|
| 운영 중인 조직 | `plants.is_active=true` 건수 |
| 등록 담당자 | `profiles.role=plant_manager`, 활성·비활성 포함 |
| 등록 사용자 | `profiles.role=player`, 활성·비활성 포함 |
| 누적 완료 세션 | `play_sessions.status=completed`, 전체 기간·재플레이 포함 |
| 현재 시즌 | 기존 관리자 `season-overview` API가 반환하는 유효한 open 시즌 |
| 경쟁 플레이 연결 | 활성 경쟁 시나리오의 활성 연결이 정확히 하나이며 현재 배포 버전과 일치하고 그 버전도 published인 수 |

튜토리얼의 로컬 플레이는 서버 세션 집계에 들어가지 않는다. 등록 계정 수는 해당 시점의 로그인 가능 인원이나 교육 참여율을 뜻하지 않는다. 시나리오 연결 수는 현재 연결 구성의 요약이며 다른 사용자별 접근 조건이나 콘텐츠 전문가 승인 완료 여부를 대신 판정하지 않는다.

## 데이터·조회 동작

- 조직·계정·학습 건수는 기존 RLS 아래 `HEAD` 요청과 `count=exact`로 조회한다. 개별 행·실명·닉네임·점수·선택 로그를 브라우저로 가져오지 않는다.
- 시즌은 기존 `admin-scenario`의 읽기 전용 `season-overview`를 사용한다. DB·Edge Function 변경이나 운영 데이터 수정은 없다.
- 수동 **현황 새로고침**으로 다시 읽는다. 한국 시간으로 마지막 조회 시각을 표시한다. 집계 요청은 독립적이며 하나의 DB 트랜잭션 스냅샷은 아니다.
- 건수 조회와 시즌 조회의 오류는 각각 표시한다. 누락된 count를 0으로 대체하지 않는다. 관리자 시즌 API가 401/403이면 건수 결과도 표시하지 않는다.
- 최신 요청만 반영하고 화면을 떠난 후 늦은 응답은 무시한다.
- 현재 시즌 없음과 시즌 조회 실패를 구분한다. 새 경쟁 플레이 연결이 0개면 시나리오·시즌 연결 관리로 안내한다. 여러 버전이 동시에 연결되면 확인이 필요한 상태로 표시한다.

## 검증

`operationsOverview.test.ts`는 정확한 0과 조회 실패 구분, 활성·배포·단일 연결 조건을 확인한다. `e2e/admin-operations-overview.spec.ts`는 두 모바일 크기에서 건수 전용 요청, 시즌 상태, 오류·재시도, 서버 거절, Player/Manager 접근 차단, 가로 넘침·axe 접근성을 검증한다. 테스트는 로컬 모의 API를 사용하고 운영 데이터를 변경하지 않는다.

실제 운영 관리자 로그인 후 조회와 모바일 실기기 사용성은 별도 확인한다.
