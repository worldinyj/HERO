## 1. 문서 우선순위

충돌 시 아래 순서로 해석한다.

1. **PRD** — 왜/무엇을 만들지, P0/P1/P2 릴리스 범위
2. **TRD** — PRD를 만족시키는 데이터·보안·엔진·배포 계약
3. **UX/UI** — PRD/TRD의 사용자 노출 방식
4. **TASKLIST** — 위 설계를 실제 구현 작업으로 분해

구현 중 요구사항을 바꾸면 **PRD 요구사항 ID → TRD → UX/UI → TASKLIST 순으로 같은 PR에서 함께 수정**한다.

## 2. 공통 도메인 계약

| 항목 | 단일 정의 |
|---|---|
| 권한 | `admin → plant_manager → player` |
| 조직 직무 | `job_role = sro / ro / field_operator / supervisor / worker` |
| 플레이 관점 | `perspective_role`; MVP는 시나리오별 고정 1개, 조직 직무와 무관 |
| MVP 접근 | 모든 active player가 S01~S03을 동일 조건으로 플레이 |
| 시즌 | KST 월 단위. 1일 00:00 시작, 다음 달 1일 00:00 미만까지 |
| 세션 점수 | 서버 재계산 `scenario_hp`, 최대 310(현재 rule version) |
| 시즌 점수 | 해당 시즌 **시나리오별 최고 scenario_hp의 합** |
| RNG | `simulation_seed`: 시즌×시나리오 공통 / `presentation_seed`: 세션별 UI 셔플 |
| 리더보드 노출 | 닉네임·발전소 표시명·조직 직무·HP·순위 |
| 담당자 노출 | 초대/수락/완료수/최근활동 + n≥5 익명 집계. 개인 점수·선택·엔딩·5대 지표 금지 |
| 회고 | `CausalReflection`: 개인 비난/정답 판정 대신 조건·방어막 누적 성찰 |
| Hidden Hazard | 교육용 상대지수. 실제 HRA 확률·개인능력 평가값이 아님 |
| 오프라인 | 온라인에서 시작한 세션만 이어하기 가능. 점수 확정은 재접속 후 서버 검증 |
| OPIS | 관리자 수동 수집 → 익명화/시스템적 HF 분석 → 전문가 승인 후 배포 |
| 오디오 | 제작 단계 AI 생성 → HF/권리/QC 승인 → `public/audio` 정적 배포. 실제 원전 경보음 유사 SFX 금지 |

## 4. 릴리스 경계

### Release 1 (P0)
- 3계층 권한, 최초 admin 부트스트랩
- 카카오 로그인 + 1회용 초대 링크 + 카카오톡 공유
- 모든 사용자가 동일한 S01~S03 플레이
- Hidden Hazard Engine, 방어막 카드, 인과 회고, Swiss Cheese, 개인 HP 리뷰, 리플레이
- 월별 시즌 리더보드 + 지난 시즌 스냅샷
- 담당자 참여/완료 현황(개인 성과 비노출)
- 핵심 운영행위 감사로그(초대·수락·권한·비활성화·점수조정·시즌마감)
- JSON 시나리오 업로드·검증·상태관리
- 모바일 우선 PWA, 시작된 세션 오프라인 이어하기
- 승인된 BGM/SFX 정적 자산, 독립 볼륨/음소거, 오디오 없이 정보동등성

### Release 2 (P1)
- OPIS PDF → AI 분석/시나리오 초안 + 전문가 승인
- 다중 관점 플레이
- 누적 리더보드·포상 CSV
- 발전소 대항전, 칭호/배지, 선택 분포, 부정행위 대시보드
- 카카오 알림톡, 카카오 미사용자 예외계정

### Release 3+ (P2)
- Team Mode, Daily Challenge, Survival Mode
- 시각 시나리오 편집기
- 사내 SSO

## 5. 구현 전 필수 일관성 테스트

- [ ] PRD의 모든 P0 요구사항이 TASKLIST Phase 0~7에 존재한다.
- [ ] Release 2/3 기능이 MVP 화면에 “현재 제공”으로 보이지 않는다.
- [ ] `job_role`과 `perspective_role`을 DB/API/UI에서 혼용하지 않는다.
- [ ] 리더보드 점수가 PRD §7과 TRD §4.3에서 동일하다.
- [ ] `simulation_seed`가 같은 시즌·시나리오에서 모든 사용자에게 동일하다.
- [ ] 발전소담당자가 개인 `hp_point`, metrics, decision log, ending을 조회할 수 없다.
- [ ] 소규모 집계(`n<5`)가 담당자 분석 화면에서 억제된다.
- [ ] “당신이 사고를 냈다/틀렸다” 문구가 사용자 화면에 없다.
- [ ] Hazard Index가 실제 HRA/HEP/위험확률처럼 표시되지 않는다.
- [ ] OPIS 원문 식별정보·설비 Tag·세부 운전값이 배포 시나리오에 남지 않는다.
- [ ] 새 세션 오프라인 시작이 차단되고, 기존 세션만 이어진다.
- [ ] WCAG 2.2 AA 핵심 모바일 기준을 E2E/실기기에서 확인한다.
- [ ] 핵심 정보가 오디오에만 의존하지 않으며 BGM/SFX mute가 독립적으로 동작한다.
- [ ] 실제 원전 경보/설비음과 혼동 가능한 SFX가 없다.
- [ ] 모든 배포 오디오가 manifest의 provenance·라이선스/HF 검수 상태와 일치한다.
