# 시나리오 승인·배포 원자적 처리

2026-10-11

기존 상태 변경은 기존 배포 버전 보관, 새 버전 상태 변경, 감사 기록 저장을 각각 수행했다. 중간 실패 또는 여러 관리자의 동시 작업으로 일부 상태만 반영될 수 있었다.

## 변경

- `set_scenario_status_atomic` RPC 한 트랜잭션에서 상태 변경·기존 배포 버전 보관·두 버전의 감사 기록을 함께 저장한다. 감사 실패 시 전체 롤백한다.
- 활성 관리자만 service-role Edge 경유로 실행한다. 브라우저/anon 직접 RPC 권한은 없다.
- 부모 시나리오를 잠가 서로 다른 버전의 동시 배포를 직렬화한다. 부분 고유 인덱스로 시나리오당 배포 버전 하나를 보장한다. 기존 중복이 있으면 마이그레이션이 실패하며 임의로 내용을 보관하지 않는다.
- 화면이 확인한 이전 상태와 서버 검증 당시의 JSON 내용을 DB 잠금 안에서 다시 비교한다. 달라졌으면 409로 거절하고 새로고침을 안내한다. 캐시된 구형 클라이언트는 Edge가 읽은 상태를 비교 조건으로 사용한다.
- 승인·배포 전 Edge에서 스키마와 그래프를 검증한다. 경쟁 시나리오 배포에는 실사건 회고가 필요하다. 서버가 검증한 내용과 DB 내용의 동일성을 RPC에서 확인한다.
- 승인자·승인 시각·배포 시각은 DB에서 기록한다. 기존 상태 전이 규칙과 시즌 연결 조건을 유지한다.

## 검증

- TypeScript, ESLint, Deno 함수 타입 검사, 빌드, 정적 DB 계약, 공유 메타데이터 통과.
- 엔진 19개 + 웹 324개 = 단위 검증 343개 통과.
- pgTAP 새 원자적 상태 변경 35개 통과. 기존 448개도 통과: 독립 스키마 DB의 금지어 기준 데이터 누락을 보완했고, pg_cron이 필요한 시즌 시험은 기존 로컬 DB의 롤백 트랜잭션에서 실행했다. 운영 DB에서 시험 데이터를 만들지 않았다.
- 실제 두 DB 연결의 서로 다른 버전 동시 배포와 같은 버전 중복 배포 통과. 첫 트랜잭션의 잠금 대기를 확인한 뒤 커밋하여 하나의 배포 버전과 정확한 감사 수를 검증했다.
- 모바일 390×844 / 360×800 미리보기·비교·상태 확인 E2E 42개 통과. 오래된 상태의 HTTP 409와 목록 새로고침 복구 포함. API 응답은 로컬 fixture이며 운영 상태를 변경하지 않는다.

## 운영 적용

CI 통과 후 마이그레이션 026 → admin-scenario Edge → 웹 순서로 적용한다. 운영 마이그레이션 016~024의 이름과 SQL은 같지만 식별자에 차이가 있으므로 전체 db push 대신 신규 SQL과 해당 이력만 같은 트랜잭션에 기록한다. 배포 완료 결과는 별도 운영 증빙 브랜치에 기록한다.
