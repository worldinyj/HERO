# 관리자 시나리오 미리보기

관리자 > 시나리오 화면에서 입력한 JSON을 저장 전 검토용으로 실행하거나, 버전 목록의 미리보기 버튼으로 저장된 특정 버전을 확인한다. 기존 엔진과 장면·정보 확인·HU Tool 카드·2탭 선택·엔딩·실사건 회고 컴포넌트를 사용한다. 같은 버전의 검토 경로를 비교하기 위해 고정된 preview seed를 사용하며 실제 시즌의 확률·점수 결과를 보증하지 않는다.

미리보기는 컴포넌트 메모리에만 게임 상태를 유지한다. 튜토리얼/경쟁 게임 저장소, IndexedDB, start-session, submit-session을 사용하지 않는다. 학습기록·HP·리더보드에 반영하지 않으며 승인·게시 상태를 바꾸지 않는다. JSON을 편집한 뒤에는 미리보기 버튼을 다시 눌러 새 사본을 확인한다.

## 검증과 실패 처리

- JSON 구문 → ScenarioSchema → 그래프 무결성을 검증한다. null/배열/불완전 객체/끊어진 장면 연결은 실행을 차단한다. 검토 경고는 오류와 구분해 표시한다.
- 저장된 버전의 응답 ID와 내용의 버전 번호가 요청과 일치해야 실행한다. 불러오기 취소 또는 다른 미리보기 시작 후 도착한 이전 응답은 폐기한다.
- 자동 장면 순환 등 엔진 실행 오류는 미리보기 경계에서 처리해 관리자 화면을 유지한다. 수정 후 다시 열 수 있다.
- 열 때 검토 제목으로 포커스를 옮기고 닫거나 취소하면 실행 버튼으로 돌아온다. 처음부터 다시 보기 및 닫기를 제공한다.

## 서버와 운영 반영

`admin-scenario`에 읽기 전용 `preview` action을 추가한다. 기존 JWT 및 활성 admin 검증 이후 UUID로 요청한 버전의 content만 읽는다. 조회 실패의 DB 오류 상세는 노출하지 않는다. draft/review/approved/published/archived 모든 저장 버전을 관리자만 검토할 수 있다. 조회 rate limit은 list와 같은 120회/300초다. 미리보기 자체는 게임 기록을 생성하지 않지만 기존 API rate-limit 카운터는 사용한다.

DB 마이그레이션은 없다. 서버 admin-scenario → 웹 순서로 배포한다. 배포만으로 경쟁 콘텐츠 승인을 변경하지 않는다.

- 미리보기 검증 단위 테스트 7개 포함: malformed 입력과 graph 오류, source 미변경, 정확한 saved ID/버전/응답 계약.

- 초기 JS 크기 게이트와 소셜 메타데이터 검사 통과. 게임 검증/미리보기 코드는 관리자 lazy 경로에 포함되며 첫 로그인 번들의 크기 한도를 유지한다.
