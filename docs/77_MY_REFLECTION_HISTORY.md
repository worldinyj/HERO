# 내 기록에서 회고 다시보기

2026-10-15. [회고 선택 보존](76_COMPETITIVE_REFLECTION_SELECTION.md)에 이어, 완료 화면을 떠난 뒤에도 본인의 선택을 확인할 수 있도록 한다. 참여자 실사용 완료 확인은 대기 상태로 유지한다.

## 사용자 경험

참여자 ‘내 기록’의 **내 회고 다시보기 → 최근 회고 불러오기**에서 최근 완료 플레이 최대 20건을 읽는다. 시나리오 제목·당시 버전·시즌·한국 시각·해당 플레이의 HP와 결말·선택한 방벽 약화 시점을 표시한다. 각 플레이 HP와 장별 최고 HP를 구분한다.

선택이 없는 과거 기록은 ‘저장되어 있지 않습니다’, 선택과 당시 장면을 연결할 수 없는 기록은 ‘연결할 수 없습니다’로 구분한다. 과거 선택을 추정하지 않는다. 조회 실패는 기존 기록 요약과 분리해 재시도할 수 있다. 버튼을 누르기 전에는 추가 조회를 하지 않는다.

## 조회 범위와 성능

`public.my_reflection_history()`는 사용자 ID 인자를 받지 않고 `auth.uid()` 소유의 완료 기록만 반환한다. 비활성 계정과 익명 요청은 거부하고, 사업소가 중지되어도 활성 계정은 본인 과거 기록을 읽을 수 있다. 관리자에게 타인의 회고를 반환하는 기능은 아니다.

시나리오가 보관·비활성 상태가 되어도 완료 당시 버전에서 회고 문구를 해석한다. 판단 장면 선택은 실제 저장된 선택 행동이 있는 경우에만 해석한다. 전체 시나리오 JSON·사용자 식별 정보·엔진 seed·평가 원문은 반환하지 않는다. 읽기 전용 함수와 완료 기록 전용 인덱스를 추가하며 점수·승인·시즌 연결·기존 데이터는 변경하지 않는다.

## 검증

- pgTAP: 본인/타인 분리, 익명·비활성 차단, 사업소 중지 중 본인 기록 유지, 보관 버전, 미방문 장면, 과거 응답 없음, 최신순과 20건 제한.
- 모바일 360px·390px: 버튼 조회, 당시 버전·HP·회고 표시, 오류 후 재시도, 빈 기록과 잘못된 응답 구분, 운영 계정에서 참여자 조회 미실행, 접근성과 가로 넘침.
- TypeScript, ESLint, 응답 검증 단위 테스트, 빌드 및 클라이언트 비밀정보 검사.

## 운영 DB 적용 사전 점검

일반 작업 폴더의 `db push --dry-run`에서 과거 운영 이력 9건의 버전명이 로컬과 다른 것을 발견했다. 운영 SQL 27건을 별도 임시 폴더로 내려받아 모두 대조했으며, 빈 줄과 끝의 빈 SQL 문장을 제외하면 저장소 SQL과 동일했다. 9건은 로컬 `202610080016`~`202610080024`와 같은 SQL이지만 운영에서는 `20261009004924`~`20261009005011`의 적용 시각으로 기록되어 있다.

기존 이력 삭제·repair·기존 SQL 재실행은 하지 않는다. 운영 이력과 일치하는 임시 작업 폴더에 검증된 `202610150028_my_reflection_history.sql` 한 건을 추가하고 dry-run으로 신규 한 건만 확인한 뒤 적용한다. Vault·역할·seed 갱신은 포함하지 않는다. 신규 함수 적용 후 웹 앱을 배포한다. 향후 일반 `db push`에서도 기존 버전명 차이는 별도로 고려해야 한다.

공통 CSS 변경으로 HTO 시안 식별 해시는 재생성하지만, S02/S03 본문·승인 해시는 바꾸지 않는다.
