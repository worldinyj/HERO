# 기존 담당자 초대링크 재생성

관리자 조직 관리 화면의 활성 담당자 행에서 `초대링크 재생성`을 선택하고 확인하면 7일 유효 일회용 링크를 발급한다. 링크는 담당자의 기존 Auth ID에 고정한다. 다른 카카오 계정으로 수락하면 403 `invitation_account_mismatch`를 반환하고 링크를 소비하지 않는다. 기존 닉네임, 동의 시각, 소속, 권한 및 학습기록은 변경하지 않는다.

재발급 시 같은 담당자에게 이전에 발급한 미사용 재접속 링크를 취소한다. 담당자와 발전소가 모두 활성 상태여야 발급·수락할 수 있다. 발전소 운영 중지로 무효화된 링크는 재활성화 후에도 복원하지 않는다. 발급, 취소 및 감사 기록은 한 DB 트랜잭션에 포함되며 감사 기록 실패 시 모두 롤백한다. 결과 불명확 또는 대상 ID 불일치 응답 시 UI는 즉시 재시도를 잠근다. 일반 신규 담당자·Player 초대 흐름은 유지한다.

‘활성’은 계정 사용 허용 상태이며 초대 링크의 유효 상태가 아니다. ‘사용할 수 없는 초대’는 이미 사용됨, 만료, 취소 또는 발전소 중지 등 여러 원인이 가능하므로 해당 메시지만으로 특정 원인을 단정하지 않는다. 기존에 가입한 담당자는 가입할 때 사용한 카카오 계정으로 일반 로그인할 수도 있다.

## 검증 (2026-10-11)

- TypeScript, ESLint, 웹 빌드 및 단위 테스트 통과: engine 19, web 304.
- 변경 Edge Function 3개 Deno 타입 검사 및 오류 분류 테스트 5개 통과.
- 로컬 PostgreSQL/pgTAP 전체 18개 파일, 448개 검증 통과. 새 기능 31개 포함.
- 기존 데이터 충돌을 피하기 위해 16개 파일은 스키마만 복제한 빈 임시 DB에서, 금칙어 seed와 pg_cron을 요구하는 2개 파일은 기존 로컬 DB에서 실행했다. 새 마이그레이션과 테스트를 같은 트랜잭션에 넣고 모든 실행을 롤백했다. 운영 DB에는 실행하지 않았다.
- 모바일 390×844 및 360×800에서 총 6개 Playwright 검사 통과. Supabase 요청을 테스트 응답으로 가로채어 확인 전 미발급, 취소, 정확한 대상 발급, 결과 보관, 불확실 응답 재시도 차단, 기존 계정 수락 UI 및 계정 불일치 안내를 검증했다. 실제 카카오 OAuth 검증은 별도 필요하다.

## 운영 반영 순서

1. 원격 마이그레이션 016–024는 로컬과 버전 ID가 다르므로 현재 상태에서 전체 `supabase db push`를 실행하지 않는다. SQL 동일성 확인 결과와 원격 migration history를 먼저 대조한다.
2. 검토한 `202610110025_manager_reinvitation.sql`만 트랜잭션으로 적용하고 해당 버전·이름·SQL을 원격 migration history에 일치시킨다. 기존 migration history를 임의로 덮어쓰지 않는다.
3. `manager-user-action`, `accept-invite`, `peek-invite` Edge Function을 배포한다. 새 컬럼 의존성이 있으므로 DB가 먼저다.
4. 웹을 빌드하고 수동 Cloudflare Pages 운영 배포한다.
5. 관리자에서 재생성 → 링크 복사 → 기존 담당자의 같은 카카오 계정으로 접속 → 기존 정보 보존을 실제 계정으로 확인한다. 다른 계정 거부와 이전 링크 무효화도 확인한다.

이 문서의 검증은 로컬 구현 검증이다. 운영 DB·Edge Function·웹 배포 또는 손병집 담당자의 실제 접속 완료를 의미하지 않는다.
