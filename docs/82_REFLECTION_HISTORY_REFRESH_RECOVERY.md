# 개인 회고 새로고침의 실패 복구 개선

2026-10-15.

## 변경

`/me`의 ‘내 회고 다시보기’는 새로고침 요청을 시작할 때 기존 기록을 지웠다. 이후 연결 오류나 잘못된 응답이 발생하면 이미 읽던 기록까지 사라졌다.

이제 새 응답의 검증이 성공할 때만 목록을 교체한다. 조회 중과 실패 후에는 기존 목록·당시 버전·HP·회고 선택을 유지하고 ‘이전 조회 결과’임을 명시한다. 첫 조회 실패와 이전 조회에서 기록이 없었던 경우도 구분한다. 유효한 빈 응답은 정상적으로 빈 목록으로 갱신한다.

## 범위

RPC와 DB·권한·정렬·20건 제한을 변경하지 않는다. 서버는 완료 세션이 참조한 정확한 시나리오 버전에서 제목과 회고 문구를 계산한다. 현재 공개된 버전으로 과거 기록을 바꾸지 않는다. 계정별 컴포넌트 분리와 관리자·교육담당자의 참여자 회고 조회 제외도 유지한다.

## 검증

- 기존 응답 검증 단위 테스트 2개 통과.
- 360px·390px에서 총 14개 모바일 검증 통과: 요청 시 조회, 최초 실패 후 재시도, 빈 기록/손상 응답 구분, 네트워크·손상 응답 새로고침 실패 시 이전 기록 유지, 복구 후 목록 교체, 관리자·교육담당자 조회 제외.
- 테스트 전용 과거 S02 v3 기록이 오류 중에도 v3·233 HP·기존 회고 선택을 유지하고, 정상 응답의 S01 v5·S03 v7 기록으로 교체되는지 확인했다. 이 데이터는 loopback mock이며 실제 참여자 기록이 아니다.
- 접근성 검사 위반·회고 영역 가로 넘침 없음.
- lint, TypeScript·프로덕션 빌드, 경로 분리·초기 로딩 용량·클라이언트 비밀정보 검사 통과.
- 공개 시나리오 본문·승인 해시 변화 없음.
