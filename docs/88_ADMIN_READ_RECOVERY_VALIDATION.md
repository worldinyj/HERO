# 관리자 운영 현황·감사 이력 조회 복구

2026-10-16. PR #140의 조직 목록 페이지 처리 후, 추가 체험 결과 없이 점검할 수 있는 관리자 읽기 흐름을 검토했다. 운영 현황과 감사 이력은 응답이 멈추면 조회 버튼이 계속 비활성화되는 문제가 있었다.

## 변경

운영 현황의 등록·학습 집계와 현재 시즌은 각각 기존 `readWithDeadline`의 15초 제한을 사용한다. 한쪽 실패·지연이 다른 쪽의 성공 결과를 없애지 않는다. 다만 시즌 API의 401/403은 기존과 같이 성공한 집계도 무효화한다. 조회 실패를 실제 0건이나 운영 시즌 없음으로 표시하지 않는다. 제한 후 새로고침 버튼이 활성화되며 자동 재시도는 하지 않는다.

감사 이력도 15초 후 지연 안내와 ‘같은 페이지 다시 조회’를 제공한다. 재시도는 적용했던 이벤트·한국 시간 날짜 범위·ID 커서를 그대로 사용한다. 아직 조회를 누르지 않은 입력값은 재시도 조건에 섞이지 않는다. ‘최신 기록 새로고침’은 기존처럼 첫 페이지를 읽는다. 잘못된 날짜 입력은 서버 조회 재시도와 구분한다.

두 화면 모두 대체 조회·화면 이탈 시 전송을 취소하고, 요청 revision으로 늦은 응답의 상태 변경을 막는다. 기존 공통 읽기 도우미는 전송 계층이 취소를 무시해도 제한 시간에 대기를 끝낸다. 새 요청이 시작되면 이전 결과를 숨겨 오래된 집계·기록을 새 결과로 표시하지 않는다.

오류 상태에서 비어 있는 감사 기록 컨테이너의 접근 가능한 이름에 유효한 역할이 없던 문제도 수정했다. 기록 목록과 페이지 작업은 이름이 있는 group으로 제공한다. 감사 `metadata`나 새 개인정보 필드는 조회하지 않는다.

이번 변경은 읽기 복구다. DB 스키마·권한·감사 기록 생성·시나리오 승인/게시·시즌 연결·초대 쓰기 요청은 변경하지 않는다. 실제 체험 의견·경쟁판 완료·내 기록 확인이나 정식 출시 승인을 대신하지 않는다.

## 검증 범위

모바일 360×800·390×844에서 기존 운영 현황·감사 이력 검사를 포함한 42건이 통과했다. 전체 단위 447건과 lint·TypeScript·프로덕션 빌드·초기 JS 예산·경로 분리·클라이언트 비밀정보 검사도 통과했다. 오류 화면 axe 위반 0·가로 넘침 없음을 확인하고 캡처를 검토했다. 브라우저 데이터는 모두 모의 응답이며 실제 계정·초대·감사 기록은 변경하지 않았다.

- 집계만 지연·시즌만 지연·둘 다 지연일 때 15초 후 새로고침 복구, 독립 결과 유지, 늦은 응답 배제
- 운영 현황 조회 도중 다른 관리 화면으로 이동 후 복귀 시 새 결과 표시
- 감사 이력 첫 조회 지연 후 다른 필터 조회, 다음 페이지 지연 후 같은 커서·적용 필터 재시도
- 오류·지연과 빈 기록 구분, 일반 사용자·담당자 접근 차단 회귀
- 오류 화면 axe 접근성·가로 넘침·화면 캡처

최종 자동 검사·CI·병합·운영 배포 근거는 해당 PR에 기록한다. 두 체험자의 상세 의견과 실제 경쟁판 완료·서버 검증·내 기록 반영 결과는 추가 접수 대기다. 실기기·오디오 QC·법무/개인정보·사내망·30명 파일럿·별도 staging/동일 SHA RC 근거는 별도 항목으로 유지한다.
