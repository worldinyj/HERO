# S03 HF Brief V1 — 절차 예상과 실제 상태가 어긋나는 순간

> **상태: REVIEW_READY — OFFICIAL NSSC SOURCE + TEXT RIGHTS + TECH GATES VERIFIED / HUMAN REVIEW 전 publish 금지**  
> 내부 저작용 문서. 실제 발전소·호기·시험명·설정치·고유 제어기기명은 공개 시나리오에서 일반화한다.

## 1. 교육 목표

S03 「절차와 실제 상황이 조금 다릅니다」는 절차를 무시하는 용기나 기계적으로 따르는 태도 중 하나를 정답으로 만들지 않는다.

- 현재 설비상태와 절차가 전제하는 상태가 같은지 확인
- 설정값의 **방향/의도**를 입력 전에 다시 확인
- 예상과 다른 추세가 보이면 Questioning Attitude 사용
- Peer Check / Three-way Communication으로 입력 의도와 결과를 공유
- 불확실하면 Stop When Unsure
- 사건 뒤에는 개인 재교육만이 아니라 절차·시스템 피드백 방어막을 개선

## 2. 원안위 공식 조사결과

원자력안전위원회는 2026년 8월 11일 신규 원전 시운전 중 자동정지 사건을 조사한 뒤 다음을 공식 발표했다.

- 송전 차단 시운전 시험 이후 출력을 복구하는 과정에서 운전원이 터빈제어밸브 위치제한기의 설정치를 입력했다.
- 예상하지 못한 출력 변동을 제한하려는 의도였으나 밸브가 닫히는 방향으로 설정치를 잘못 입력하여 원자로가 자동정지했다.
- 사업자는 동일 인적오류 방지를 위해 관련 시험·운전 절차를 보완하고 특별교육을 실시했다.
- 구체적으로 위치제한기 조작 시 **재확인하도록 절차서를 보완하고 운전 시스템에 반영**했다.
- 원안위는 사건조사와 사업자의 조치 및 재발방지대책을 검토했다.

공식 출처:
- 원자력안전위원회/정책브리핑, 2026-09-04: https://www.korea.kr/briefing/pressReleaseView.do?newsId=156780201

이용조건:
- 정책브리핑은 해당 보도자료 텍스트를 **공공누리 제1유형(출처표시)** 조건으로 이용할 수 있다고 명시한다.
- 사진·이미지·일러스트·동영상은 별도 권리 확인이 필요하므로 HERO에는 사용하지 않는다.
- HERO 공개문안은 원문 문장을 복사하지 않고 사건사실을 익명화·일반화하여 독립 작성한다.

## 3. HERO에서 일반화하는 부분

공개 시나리오에서는 다음을 제거한다.

- 실제 발전소/호기
- 실제 시험 출력과 시각
- 실제 기기명과 세부 설정치
- 실제 조작 화면/운전절차를 재현할 수 있는 구체적 순서

대신 “상태전환 시험 후 출력 복구”, “조절기 제한값의 방향”, “예상과 다른 설비추세” 수준으로 일반화한다.

## 4. HF 모델

### 확인된 재발방지 방향

- 조작 전 재확인 단계의 절차 보완
- 시스템상 재확인 지원
- 사건 기반 교육/훈련

### 게임용 PSF 가설

- `mode_transition`: 시험/상태전환 직후의 복잡성
- `direction_ambiguity`: 설정 방향 해석 불확실성
- `time_pressure`: 복구를 이어가야 한다는 압박
- `expectation_bias`: 예상한 반응을 볼 것이라는 기대

> 게임용 PSF는 공식 원인분류가 아니다.

### 핵심 방어막

- Questioning Attitude
- Peer Check
- Three-way Communication
- Place Keeping
- Stop When Unsure

## 5. 결정 구조

### Decision 1 — 절차의 예상과 실제 추세가 다를 때

- 현재 상태를 절차 전제와 다시 맞춤
- 동료와 추세/의도를 공유
- 일시적 변동으로 보고 예정된 다음 단계 진행

### Decision 2 — 설정 방향을 입력하기 전

- 독립적인 Peer Check로 방향 확인
- Place Keeping으로 현재 단계·입력 의도를 재확인
- 입력 후 반응을 보며 조정

### Hidden Hazard

입력 방향의 불확실성과 방어막 강도, 동일 simulation seed로 판단한다.

### Recovery

예상과 반대되는 추세가 나타난 경우:
- 입력 중지·상태 안정·보고
- 팀과 원인을 확인한 뒤 제한적 복구
- 즉시 반대 방향 입력으로 상쇄 시도

## 6. Just Culture 해석

공식자료가 직접적인 입력 오류를 사건 원인으로 설명하더라도, HERO의 학습은 다음으로 확장한다.

- 왜 입력 전 재확인 단계가 필요했는가
- 시스템이 방향 오류를 더 일찍 알아차리도록 도울 수 있는가
- 절차가 언제 재확인을 요구해야 하는가
- 팀 커뮤니케이션이 입력 의도와 실제 반응의 차이를 어떻게 포착할 수 있는가
