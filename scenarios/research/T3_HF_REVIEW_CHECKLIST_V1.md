# HERO 경쟁 시나리오 HF·익명화 검토 체크리스트 V1

> 적용: S01~S03 및 이후 모든 실사건 기반 경쟁 시나리오  
> 목적: T3-09 콘텐츠 검토를 반복 가능한 승인 게이트로 표준화

## A. 근거와 사실성

- [ ] 공식 사건 원문(OPIS/원안위/KINS 등)을 식별했다.
- [ ] 원문 URL/문서명/게시일/확인일을 내부 연구문서에 기록했다.
- [ ] 공개자료의 이용조건을 확인했다.
- [ ] “공식 사실”, “HF 해석”, “교육적 재구성”을 문서에서 구분했다.
- [ ] 언론 단독정보는 공식자료 대조 전 핵심 사실로 사용하지 않았다.
- [ ] 사건의 시간순서와 재발방지대책을 원문과 대조했다.

## B. Just Culture / 원인구조

- [ ] 원인을 “작업자 실수” 하나로 종결하지 않는다.
- [ ] 절차, 설계/HMI, 감독, 작업계획, 인력/조직조건, 커뮤니케이션 중 관련 요소를 검토했다.
- [ ] 잠재조건과 현장 행동의 상호작용을 설명한다.
- [ ] 안전한 중지(Safe Stop)를 실패로 표현하지 않는다.
- [ ] 결과문구가 비난·조롱·능력평가로 읽히지 않는다.
- [ ] 관리자나 리더보드가 개인 학습지표를 인사평가로 오해하게 만들지 않는다.

## C. 익명화·보안

- [ ] 발전소명/호기 제거
- [ ] OPIS 사건번호 제거
- [ ] 실제 개인/회사/협력업체 식별정보 제거
- [ ] 고유 설비 Tag/밸브·차단기 번호 제거
- [ ] 실제 운전값·보호정정값·민감한 시험조건을 일반화
- [ ] 실제 경보음과 혼동될 수 있는 오디오 단서를 사용하지 않음
- [ ] 시나리오만으로 실제 설비 조작 절차를 재현할 수 없도록 검토

## D. 학습설계

- [ ] 모든 주요 결정지점에 3~4개의 그럴듯한 선택지가 있다.
- [ ] 표시순서와 무관한 stable `actionId`를 사용한다.
- [ ] 선택지에 정답처럼 보이는 도덕적 문구를 쓰지 않는다.
- [ ] 정보행동은 시간을 사용하지만 실제로 판단정보를 제공한다.
- [ ] HU Tool 카드는 사건 방어막과 근거 있게 연결된다.
- [ ] Hidden Hazard Index를 사용자에게 위험확률/HEP로 표시하지 않는다.
- [ ] safe_complete / safe_stop / near_miss / event의 교육적 의미가 구분된다.
- [ ] 실사건 공개는 플레이 종료 후에만 노출한다.

## E. 기술·밸런스

- [ ] `pnpm validate:scenario <file>` PASS
- [ ] `pnpm simulate:scenario -- --scenario=<file>` COMPLETE
- [ ] 시뮬레이션 error 0
- [ ] `dominant_choice_bias` 경고 0 또는 예외 사유 기록
- [ ] 한 엔딩이 90% 이상이면 의도 여부를 검토
- [ ] 모든 선택에서 최소 하나의 엔딩 경로가 존재
- [ ] replay가 원 세션을 변경하지 않음
- [ ] 서버 seed/로그 재실행 결과와 클라이언트 결과가 동일
