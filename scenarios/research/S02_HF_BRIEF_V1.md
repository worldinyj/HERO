# S02 HF Brief V1 — 작업 대상·조작부 식별 오류

> **상태: RECOMMENDED DRAFT / publish 금지**  
> 내부 저작용 문서. 실제 게임 공개 화면에는 발전소·호기·사건번호·고유 설비명·개인정보를 노출하지 않는다.

## 1. 교육 목표

플레이어가 “사람이 버튼을 잘못 눌렀다”는 결론에 머무르지 않고 다음을 함께 보게 한다.

- 작업 대상과 조작부의 **식별 가능성**
- 작업 전 설비/회로 상태 확인
- Self Check(STAR)와 독립확인/Peer Check
- 불확실할 때 멈추고 감독자·동료에게 확인
- 잠재 설비조건과 현장 행동이 겹칠 때 방어막이 어떻게 약해지는지

## 2. 확인된 사건 사실과 교육적 재구성 분리

### 공개자료에서 확인된 사실

- 정기검사 전 국내 원전에서 터빈·발전기 정지에 이어 원자로가 정지한 사건이 있었다.
- 원안위 조사결과를 인용한 보도에 따르면 여자계통의 차단기 회로가 잘못된 상태였고, 정비원이 차단기 버튼을 상태표시등으로 오인해 조작한 조건이 결합했다.
- 회로가 올바른 상태였다면 해당 조작만으로 정지되지 않았을 것이라는 원안위 설명이 보도되었다.
- 사업자는 회로 정비와 인적오류 방지 설비개선 등 재발방지책을 마련했다.

### 아직 확정하지 않는 사실

- 구체적인 작업지시서 내용
- 현장의 정확한 인원구성 및 감독자 위치
- 실제 패널/버튼 형상, 색상, 표기
- 실제 회로 번호·설비 Tag
- 작업자가 어떤 인지과정으로 오인했는지에 대한 심리적 단정

위 항목은 원안위/OPIS 원문을 확보하기 전까지 **교육적 재구성 또는 미확인**으로 취급한다.

## 3. HF 모델

### 잠재조건

- 설비/회로 상태가 의도와 다르게 구성된 조건
- 조작부와 상태표시의 구분성 부족 가능성
- 정비 전 작업경계와 상태확인 방어막의 취약 가능성

### 오류유발조건(PSF) — 게임용 가설

- `identity_ambiguity`: 비슷한 외형·표현으로 인한 대상 식별 불확실성
- `time_pressure`: 작업 진행 압박
- `uncertainty`: 현재 상태와 문서정보가 완전히 일치하지 않는 느낌

> 위 PSF는 **게임 모델링 변수**이며 사건조사기관의 공식 원인분류를 의미하지 않는다.

### 핵심 방어막

- Self Check (STAR)
- Peer Check
- Independent Verification
- Stop When Unsure
- 절차/작업경계 재확인
- 감독/작업팀 커뮤니케이션

## 4. 시나리오 결정 구조

### Decision 1 — “이 조작부가 맞는가?”

가능한 행동을 정답/오답으로 쓰지 않고 시간·정보·확인수준의 trade-off로 만든다.

- 표식과 현장 상태를 가까이서 다시 확인
- 작업 문서/도면과 현장 상태를 대조
- 현재 기억과 주변 맥락을 근거로 진행

정보행동:
- 상태표시와 조작부의 구분 단서 확인
- 작업경계/문서의 식별정보 추가 확인

### Decision 2 — “확신이 완전하지 않을 때 어떤 방어막을 세우는가?”

- 독립확인을 요청
- 작업을 잠시 멈추고 감독자/동료와 상태를 확인
- Self Check 수준에서 진행

카드:
- `self_check_star`
- `peer_check`
- `independent_verification`
- `stop_when_unsure`

### Hazard — 식별/상태 불확실성이 남은 채 조작

Hidden Hazard Index에서만 판정하며 UI에 위험수치를 보여주지 않는다.

- 충분한 방어막 → 정상 대상 확인
- 방어막 취약 → 예상하지 못한 설비 반응

### Recovery Decision

예상하지 못한 반응 뒤에도 “누가 잘못했나”가 아니라 **어떤 방어막을 다시 세울 것인가**를 묻는다.

- 즉시 중지·보고·상태보호 → Safe Stop
- 상태를 다시 확인하고 복구 시도 → Near Miss 또는 Event
- 일시적 현상으로 가정하고 계속 → Event 가능성 증가

## 5. 엔딩 의도

| 엔딩 | 학습 의미 |
|---|---|
| safe_complete | 확인 방어막을 사용해 작업 대상을 명확히 하고 완료 |
| safe_stop | 불확실성을 인정하고 작업을 안전하게 중지 |
| near_miss | 예상치 못한 반응 뒤 추가 확인으로 확대를 막음 |
| event | 취약한 방어막 상태에서 계속 진행해 사건으로 이어짐 |

모든 엔딩은 개인의 도덕적 평가가 아니라 **조건과 방어막의 결과**로 설명한다.

## 6. 공개 Incident Debrief 원칙

공개문안에는 실제 발전소/호기/설비 Tag를 제거하고 다음 수준만 남긴다.

- 사건유형: 작업 대상/조작부 식별 오류 + 잠재 설비상태
- 근본원인: 식별·상태확인·독립검증 방어막의 취약
- 기여요인: 유사한 표시/조작 요소, 설비상태의 잠재조건, 확인·커뮤니케이션 조건
- 교훈: STAR, Independent Verification, Stop When Unsure, Peer Check
